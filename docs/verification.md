## 記録

### 初期実装の通し（2026-11-21）

**対象**：SPEC F1〜F17・N1〜N5。**操作**：次の順に、コマンドと、ブラウザ（`browser`）で行った。

1. `rikai new auth-flow …`（標準入力から Markdown。Mermaid・表を含む）→ `rikai open … --no-open`。
2. 合言葉なしで `GET /api/topics`。→ **403**。
3. HTTP で `POST /api/comment`（アンカーつき）→ `POST /api/submit`（round 1）→ `rikai pull`・`rikai poll`。
4. 誤った `apply`（存在しない `thread`・空の `body`・不正な ID・存在しない `parent`・存在しないページへの改訂）→ `errors` が 6 件返り、終了コード 1。
5. 正しい `apply`（返信・改訂・子ページ・AI 起点のスレッド・`ask`）→ `handledRounds:[1]`・`newPages`・`revised:{root:2}`・`repliedThreads`・`newThreads`。`rikai status` で `pendingRounds:[]`。
6. 待機中の `rikai poll`（バックグラウンド）が、別の呼び出し（`POST /api/submit`。全体メモのみ）で終わること（round 2。`items:[]`・`overallNote`）。
7. ブラウザで、トピックを開く：Mermaid の図・表・変更ブロックの印（v2 の新しい段落と直した段落）・スレッド 2 件（文のアンカーの強調・`ask`・「詳しく見る」カード・「資料を v2 に更新」）。
8. ブラウザで、本文の文を選択（合成した `Selection` ＋ `mouseup`）→「コメント」→ 追加。ブロック（表）の「＋」→ ブロックへのコメント。
9. ブラウザで、`single_choice` の回答を選んで「回答を保存」、`multi_choice` も。→「保存済み（未送信）」・「Submit (4)」。
10. ブラウザで Submit（全体メモつき）→ round 3。`rounds/003.json` に、回答（`answer`）・コメント（`comment`）・全体メモが入る。
11. `apply`（返信 4 件・v3 への改訂・子ページ `token-issue`。子ページに画像・`<script>`・`<img onerror>`・`[x](javascript:…)` を含む）→ `handledRounds:[2,3]`。
12. ブラウザが自動で v3 に追従し、「AIの返信待ち」が消え、4 つのスレッドが「AIの返信」になること。変更ブロックの印（表・追加の段落）。外部画像のブロック（`.img-blocked` が 1）。
13. 「詳しく見る」→ 子ページ：パンくず（「認証の流れ › トークンの発行」）・`assets/shot.png` の表示（`naturalWidth > 0`）。`<script>`・`onerror` 属性は 0 件。`javascript:` のリンクは出ない（文字として表示）。
14. 版の切り替え（`#/auth-flow/root/v1`）：「過去の版 v1 を表示中」・最新版へのリンク・後の版のコメントの印。
15. 返信を追加 → 編集 → 「理解できた（解決）」→「解決済み (1)」に折りたたまれる。「Submit (2)」。
16. `install.sh` を、`CLAUDE_SKILLS_DIR=/tmp/rk-skills` で実行し、`SKILL.md`・`public`・`rikai.js` がコピーされること。

**観測した結果**：上の 1〜16 は、期待どおり（または、下の不具合を直したあとで、期待どおり）。

**見つけて、直した不具合**（どちらも、この通しの中で見つけ、同じ初期実装の PR に含めた）：

| 不具合 | 原因 | 直し方 |
|---|---|---|
| `rikai poll`・`pull` の出力の `status` が `feedback` でなく `pending` だった | round のレコードの `status: 'pending'` が、出力の `status: 'feedback'` を上書きしていた（`{status:'feedback', ...round}` の順） | 出力を `{...round, status:'feedback'}` の順にした。直したあと、`poll` が `feedback` を返すことを確認 |

- **ほかのブラウザ（Safari・Firefox）・Windows・Linux**：未確認。
- **長い資料・多数のスレッド**での速さ：未測定。

### 画面の操作の確認（2026-11-21。RIK-004）

**対象**：SPEC F5・F10・F13〜F16・F19。**環境**：上の表と同じ。一時のプロジェクトに、作り物の 2 つのトピック（「UI確認」「別のトピック」）。サーバーは、操作のあと `rikai stop`（または全トピックの終了による自動終了）で止めた。

**操作と観測**（ブラウザ。クリック・入力は、ページの DOM への `click()`・`input`/`change` イベントの発火で行った）：

| 操作 | 観測 |
|---|---|
| `single_choice`（`allowOther`）：「B案」を選んで保存 → 「その他」に文字を入れて保存 | 保存された回答が `{choice:"b"}` → `{other:"C案（その他）"}` に置き換わる（未送信の回答は 1 件のまま） |
| `multi_choice`（`allowOther`）：X と Z を選び、その他に文字を入れて保存 | `{choices:["x","z"], other:"W（その他）"}` |
| `yes_no`：「いいえ」を保存 | `{value:false}` |
| `scale`（1〜5、両端のラベル）：「4」を保存 | `{value:4}`。ボタン 5 つが出る |
| `free_text`：入力して保存 | `{text:"…"}` |
| 保存した回答の「取り消す」 | その回答が消える |
| 選択 → 「コメント」→ 追加 → 「削除」 | スレッドが消える（8 件 → 7 件） |
| ページの再読み込み | 下書きのコメント・保存した回答（選択・文字）が、そのまま出る。「保存済み（未送信）」 |
| 返信の Markdown の `[こちら](page:child)` を押す | `#/ui/child` へ移り、パンくずが「UI確認 › 子ページ」 |
| Submit（ダイアログ） | round 2 に、回答 4 件・コメント 1 件が入る。送信後、回答欄が無効になり「回答を送信済み」が 4 つ出る |
| 「理解できた（解決）」→「解決済み (1)」→「再開する」 | 解決済みの折りたたみに入り、再開で戻る |
| 返信欄で ⌘/Ctrl＋Enter（`keydown` の発火） | 返信が追加される |
| 「AIの返信待ち」の「コピー」 | トースト「コピーしました」（クリップボードの中身までは、確認していない） |
| 別のトピックを左の一覧から選ぶ | ハッシュと題名と本文が切り替わる。現在のトピックが強調される。Submit 済みのトピック（「UI確認」）に、サイドバーで「待ち」の印が付いている |
| 「終了」（`confirm` は常に「はい」に差し替え） | 終了の表示が出る。`meta.json` の `closed` が `true`。ほかのトピックが開いている間は、サーバーは動き続ける |
| すべてのトピックを終了 | サーバーが終了する（`.server.json` が消え、疎通できなくなる）。`rikai poll` は、サーバーが止まっていても `closed` を返す |

**見つけて、直した不具合**：

| 不具合 | 原因 | 直し方 |
|---|---|---|
| 「解決」→「再開」と往復しただけで、Submit の件数が増え、`userMarked: "reopened"` が AI に届いた（round 2 の `t13`） | `resolve` が、状態が変わるたびに「未送信の変更」にしていた（元の状態に戻ったかを見ていなかった） | AI が最後に知っている状態（`resolveSent` が真ならいまの状態、偽ならその逆）と、新しい状態を比べる（`setResolved`）。自動テストを足し、実装を壊して失敗することを確認。ブラウザで、往復のあと件数が増えないことを確認 |
| あるトピックを終了すると、全面の表示が、ほかに開いているトピックへの移動を塞いだ | 全面の表示が、固定の文だけだった | ほかに開いているトピックがあれば、リンクを出す。なければ、「このタブは閉じて構いません」。ブラウザで、リンクが出ること・移ると消えること・全部終了で文が変わることを確認 |

**直す途中で、自分が作った不具合**：上の 2 つ目の直しで、`replaceChildren` に配列を渡し、リンクが `[object HTMLParagraphElement]` という文字になった。ブラウザでの確認で見つけ、展開して渡すように直した（レビューより前に、確認で見つかった）。

**独立レビュー**（reviewer。read-only。ブラウザは開かず、コードと、`/tmp` の一時の手順で確かめた）：ブロッカーなし。Major 2 件（SPEC §6 の F19 が、記録にない「クリップボードの中身」を確認済みとしていた／F15 が、記録にない「待ち」の印を確認済みとしていた）・Minor 3 件・Nit 1 件。**すべて直した**：
