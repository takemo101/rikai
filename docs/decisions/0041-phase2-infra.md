# ADR-0041 整理フェーズ ②（インフラ）の判断

- 日付：2026-11-24
- 種別：AI の設計の判断（もとは、SPEC.md の §8 の表の 1 行。文言は、そのまま移した）
- 関連の機能：[F47](../features/ui-cleanup.md#f47-小さな-ui-の直し)
- 決定の元：[利用者の決定](user-decisions.md)（2026-11-24「整理フェーズ ②（インフラ）の、利用者の決定（整理分…」）。文中の「上の…」は、この決定を指す。
- 一覧：[ADR の一覧](README.md)・[SPEC.md の §8](../../SPEC.md#8-利用者の判断)

（AI の判断。上の決定の範囲。0.27.2。整理フェーズ ②）

- **(1) `events.test.ts` の間欠的な失敗の修正**：原因は、`fs.watch` が、購読のあと非同期に始まるため、`ready` の直後の書き込みが、負荷が高いと、見逃されること（全ファイルの並列実行のときだけ）。**テストの側を直した**（待ちの上限を伸ばし、届くまで最大 5 回、書き直す形）：サーバーの動作は、変えていない。
- **(2) e2e の不安定の直し方**：固定の待ちでなく、条件を待つ（`expect.poll`・`clickUntilPicked`・`clickToCount`）。**`theme.spec` の NaN は、最初は、原因が分からず、直さなかったが、独立レビューのあと、原因を特定して、直した**：本文の描き直しで、要素が外れたあとに読むと、`getComputedStyle` が空文字列を返す。外れた要素・空の値は、読み直す（`readStyle`）。**`compare.spec` の枠の中の押下**も、枠のハンドラーが付く前に押すと取りこぼすので、数が増えるまで、押し直す形にした（押し過ぎで超えない：`clickToCount`）。**この修正のあと、`workers: 4` で、5 回連続で全件成功**（担当の報告）。
- **(3) 範囲選択と要素選択を、排他にした**：実際の Chrome で、同時にオンにできていた（どちらの操作も、同じ本文の押下を取るので、どちらが効くか、分からなくなる）。**あとから始めた側が、先の側を止める**（利用者が、いま選んだ操作を、優先する）。
- **(4) 版が 1 つのページでは、「並べて比べる」を出さない**：押せないボタンを見せると、「壊れている」と見える。押しても、理由をトーストで言うだけで、できることがない。**2 版になれば、出る**。
- **(5) 関連の線のボタンの名前を、動作から「関連の線」に変えた**：名前が「関連の線を出す」で、`aria-pressed="true"`（出ている）だと、読み上げが食い違う。状態は、`aria-pressed` と `title` に任せる。
- **(6) アンカーの注記の長い `label` は、画面でだけ省略した**：保存される `anchor.label` は、AI に届く値で、変えると、データの形に関わる（見送った「範囲のラベルの元の注意文を短くする」も、同じ理由）。
- **(7) 「Claude Code 以外は…」の案内は、初めて「AI の返信待ち」になったときだけ、見える文字で出す**：常に出すと、画面が混む。2 回目以降は、コピーのボタンの `title` に残る。
- **(8) 残る課題**：Submit のそばの専用ヒントは、フェーズ ③ の P2 と一緒に行う（利用者の、動く見本の確認を経る）（[検証記録](../verification.md)）
