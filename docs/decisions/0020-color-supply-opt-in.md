# ADR-0020 配色の供給をオプトインにした

- 日付：2026-11-23
- 種別：AI の設計の判断（もとは、SPEC.md の §8 の表の 1 行。文言は、そのまま移した）
- 関連の機能：[F40](../features/html-app.md#f40-html-app-の枠と画面をつなぐ橋)
- 決定の元：[利用者の決定](user-decisions.md)（2026-11-23「html を強化していく。デザインの比較・UI のレ…」）。文中の「上の…」は、この決定を指す。
- 一覧：[ADR の一覧](README.md)・[SPEC.md の §8](../../SPEC.md#8-利用者の判断)

（AI の判断。独立レビューの指摘への対応。F40）**配色の供給を、オプトインにした**：中身に `var(--color-`・`<meta name="color-scheme"`・`data-theme` のどれかがある枠だけ、土台のスタイルと、ダークへの追従を付ける（`followsTheme`。単純な包含：誤検出は、土台が付くだけで、安全側）。**理由：従来の資料の見た目を守るため**（すべての枠に土台を付けると、ダークで、背景色だけを書いた資料の文字が、ほぼ同じ色になる・ライトでも、何も書かない資料の余白・フォント・文字色が変わった）。**従来の資料は、従来どおり、常にライト**（F36 (8) を、「オプトインした枠は」に直した）。`theme` メッセージに `by: 'auto'｜'user'` を足した（画面の外観の変化は、オプトインした枠だけ・ツールバーの操作は、どの枠でも）。**幅の切り替えは、縮小表示にした**：普通の窓では、本文が最大 760px で、768・1280・1920 を選んでも、自動と同じ幅になり、意味がなかったため。選んだ幅でレイアウトを計算し、本文より広ければ `transform: scale()` で縮めて見せる（DevTools のデバイスモードと同じ。デスクトップの幅そのものでの表示は、入れない）。**`100vh` ＋余白の循環**は、同じ増え方を 2 回で検出し、大きい側を 1 回報告して止め、`overflow-y: hidden` にした（スクロールバーを出さないため。余白の数 px が切れることがある）（[検証記録](../verification.md)）
