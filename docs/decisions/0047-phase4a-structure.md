# ADR-0047 整理フェーズ ④a：構造の整理

- 日付：2026-11-24
- 種別：AI の設計の判断（もとは、SPEC.md の §8 の表の 1 行。文言は、そのまま移した）
- 決定の元：[利用者の決定](user-decisions.md)（2026-11-24「整理フェーズ ③b の、利用者の決定（動く見本で、1…」）。文中の「上の…」は、この決定を指す。
- 一覧：[ADR の一覧](README.md)・[SPEC.md の §8](../../SPEC.md#8-利用者の判断)

（AI の判断。整理フェーズ ④a。RIK-059）**見える動きを変えない、構造の整理にした**：整理分析の指摘（`api/queries.ts ↔ lib/view.ts ↔ store/ui.ts` の循環・`store/ui.ts` が 599 行で、5 つの関心事を持つこと・層の逆転〔ストアが、`doc/`・`htmlapp-bridge` を import〕）を、**振る舞いを変えずに**直す。**独立レビューを受けた**（Blocker・Major・P2 なし。旧新の差分テスト〔20 通り・7,382 手〕と、実際の Chrome の 24 段の比較で、見える動きは同じ：[検証記録](../verification.md)）。

- **(1) スライス化の方針**：**`useUi`・`UiState`・`UiStore`・`initialUi` の名前・型・振る舞いは、不変**（import する 45 ファイルを、変えない）。**1 操作 = 1 回の `set`**（購読者が、中間の状態を見ない）：複数のスライスにまたがる操作は、ほかのスライスの項目を直接書かず、そのスライスが公開する「次の状態を返す純粋関数」を、自分の 1 回の `set` に合成する。
- **(2) `getView` は、作成時に注入する**（`createUi({ getView })`・`bindView`）：ストアが `lib/view` を import すると、`api/queries.ts ↔ lib/view.ts ↔ store/ui.ts` の循環になる。注入にして、**実行時の循環を 0 にした**。**結んでいないと、使った時点で throw する**（黙って「版なし」にすると、バグを隠す。結び忘れで throw することは、単体で固定した）。型だけの循環（スライス ↔ `createUi.ts`）は、1 件残る：スライスが `UiStore` 型を参照するため。Zustand のスライスの型の書き方どおりで、実行時には何も起きないので、許容した。
- **(3) 既に複数回の `set` の操作は、そのまま残した**：`closeComposer`（2 回）・`leaveTopic`（2 回）・`loseComposerDraft`・`focusThread`（選択と「見た」の印で 2 回）・`startComposer` と `removeFrameMeta` のトースト併用。1 回の `set` にまとめると、購読者が見る中間の状態が変わり、**観測できる動作が変わる**ので、この整理の範囲外（別に判断が要る）。**その回数を、テストで固定しなかった**（レビューの P3：実装の偶然を固定することになるため。見たいのは「1 回のものを 2 回にしない」方向で、それは `slices.test.ts` が見ている）。
- **(4) 層の逆転は、定数・型を下の層へ移して解消した**：`FRAME_IMAGE_NOTE`（`shared/htmlapp-note.ts`）・`FrameWidth`／`FRAME_WIDTHS`（`web/lib/frameWidth.ts`）。**検査の本体は、書き換えていない**。
- **(5) 小さな境界の移動も、本体を書き換えない**：`parseResize`・`normAnchor`／`normRect` は、置き場だけを変えた（`diff` で 1 文字も変わらないことを、レビューが確認した）。`submit` の `compact` は、`compactMessage` に出して、型で守った（`as unknown as Record` をやめた。キーの順・`!= null` で省く規則は、同じ：round ファイル・`pull`・`poll` の出力が、時刻を除いて、新旧で同じことを、レビューが確認した）。
- **(6) 見えない差**：スクリーンショットの差（担当の比較で 15 枚中 5 枚が 5〜7 ピクセル・レビューの比較で 24 枚中 7 枚が 2〜5 ピクセル）は、描画の揺らぎと見ている（レビューは、旧を 2 回動かして、同じ場所で、同じ程度の差が出ることを確かめた。状態のオブジェクトのキーの並び順だけが違うが、並びに頼るコードは、見つからなかった）（[検証記録](../verification.md)）
