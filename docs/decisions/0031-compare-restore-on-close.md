# ADR-0031 比べる画面を閉じるときの復元

- 日付：2026-11-24
- 種別：AI の設計の判断（もとは、SPEC.md の §8 の表の 1 行。文言は、そのまま移した）
- 関連の機能：[F44](../features/versions.md#f44-版を並べて比べる)
- 決定の元：[利用者の決定](user-decisions.md)（2026-11-23「一旦全ての依頼の実装を全て進めてほしい。明日朝あたり…」）。文中の「上の…」は、この決定を指す。
- 一覧：[ADR の一覧](README.md)・[SPEC.md の §8](../../SPEC.md#8-利用者の判断)

（AI の判断。F44 の独立レビューの指摘への対応）**比べる画面を閉じるとき、控えた入力欄・スレッドの選択・スクロール位置は、見ている版が同じ（`View.key` が同じ）ときだけ、戻す**：版が同じなら、本文は変わらないので、入力欄の対象のブロックは、まだ本文にある。**新しい版が届いて最新版が替わった・ページを移ったときは、戻さない**（対象のブロックが、あるとは限らず、書きかけの文・範囲の画像が、別のコメントに付く恐れがあるため。書きかけの文・画像は、下書きとして残る）。**別の入力欄が、すでに開いていれば、そちらを優先する**。**スクロール位置は、開く前の位置を控え、通常の本文の描き終わりに、1 度だけ戻す**（2 フレーム後にも置き直すが、その間に利用者が動かしていれば、置き直さない）。**ブロックの種類が違えば、内容が同じでも「変更」にした（F11 にも効く）**：段落 → 見出しは、意味の変更で、札が出ないと、比べる目的に反する。**対応づけは保つ**（追加と削除にしない）。差分の箱に、「ブロックの種類が変わりました：p → h2」と注記する。リストの項目は、並びの種類（箇条書き・番号つき）も含める。**F11 の対応づけの予算（`MAX_PAIRS`）を超えた全面の書き換えは、比べる画面の上に、「変更が多すぎて、対応づけていません（追加と削除として並べています）」と出す**（`limited`。追加 4000＋削除 4000 になることは、描画が軽いので、許容した）。**偽の `esc` が比べる画面を閉じることも、許容した**（個別表示と同じ）（[検証記録](../verification.md)）
