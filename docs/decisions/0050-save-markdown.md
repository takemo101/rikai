# ADR-0050 Markdown を保存の仕様と設計

- 日付：2026-11-24
- 種別：AI の設計の判断（もとは、SPEC.md の §8 の表の 1 行。文言は、そのまま移した）
- 関連の機能：[F50](../features/versions.md#f50-markdown-を保存)
- 決定の元：[利用者の決定](user-decisions.md)（2026-11-24「（利用者の依頼。F50。0.30.0。RIK-062…」）。文中の「上の…」は、この決定を指す。
- 一覧：[ADR の一覧](README.md)・[SPEC.md の §8](../../SPEC.md#8-利用者の判断)

（AI の判断。F50「Markdown を保存」。0.30.0。RIK-062）

- **(1) 保存するのは、いま見ているページ・版の、元の Markdown**：コメント・差分の装飾は含めない（本文の書き出しという依頼の範囲。コメントつきの書き出しは、別の機能）。**画像は参照のままにして、zip は作らない**（画像のファイルまで含める機能は、別に判断する）。
- **(2) サーバーを増やさない**：App がすでに取っている本文（`usePage`）を、ブラウザ側で `Blob` と `<a download>` にする。新しい経路・通信・認証の検討が要らず、押しても通信が起きない。
- **(3) 置き場所は、`#docbar` でなく、上のバー `#top`**：`#docbar` は、幅 1360px・右のコメント 380 の「過去の版」で、幅 750px のうち約 690px を使い、ボタンを足すと 2 行に折り返して、F48 の「1 行」を壊す（ラベルつき 140px でも、「保存」だけの 66px でも入らない）。また、版が 1 つのルートページでは、`#docbar` を出さない（0.28.0）ので、そこでも使える場所が要る。560px 以下はアイコンだけ（`.turn-t` と同じ扱い）・420px では `#top` の余白を詰めた。
- **(4) 並べて比べる画面では出さない**：左右のどちらの版か決まらず、片方を選ぶ根拠がない。
- **(5) 成功のトーストは出さない**：ブラウザ側の保存の結果は、見えず、「保存しました」と言えない。Blob を作れなかったときだけ、エラーのトースト。
- **(6) 取得中・取得失敗のあいだは押せない**：前の版を、新しい版の名前で保存しない。
- **(7) ファイル名の消毒は、多重防御**：slug は、`checkSlug` で、英小文字・数字・ハイフンだけと検査済みだが、保存先の名前に使うので、英数字以外を `-` にした（単体テストで固定）。
- **(8) 独立レビューは、受けない**：小さな機能で、安全の観点（ファイル名・内容・Blob）は、単体・e2e（保存したファイルを、サーバーの `.md` と、バイト単位で比べた）で確認した。詳細：[docs/verification.md](../verification.md)
