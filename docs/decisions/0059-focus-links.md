# ADR-0059 拡大表示にも「関連の線」を引く：共用部品・`ui.links` の共有・760px 未満は引かない

- 日付：2026-11-25
- 種別：AI の設計の判断（0.1.5）
- 関連の機能：[F55](../features/zoom.md#f55-拡大表示でも関連の線で結ぶ)・[F35](../features/appearance.md#f35-コメントと本文の対象を線で結ぶ)・[F43](../features/zoom.md#f43-個別表示でコメントする)・[F25](../features/region-element.md#f25-本文の好きな範囲を選んでコメントできる)
- 決定の元：[利用者の決定](user-decisions.md)（2026-11-25「本文ではコメントと対象の範囲・文が線でつながっている。画像・html-app・図形を拡大したとき、横にコメントが出るが、繋がりが番号しかない。同じように線でつなげて表現することは可能ですか」→ 方針を示して「はい、お願いします。進めてください」→ 動く見本で「全体的にいい感じなので、レビューして問題なければこれで進めて欲しい」）。
- 一覧：[ADR の一覧](README.md)

## 決めたこと

### 拡大表示にも、本文と同じ線を引く

- **ステージ上の範囲の枠（`.fv-box`）と、右のドックのコメントのカードを、本文と同じ「関連の線」で結ぶ**（画像・Mermaid／draw.io／インライン SVG の図・html-app）。`focus/FocusLinks.tsx`。
- **端点**：ステージ側は、枠の右端の縦の中央の外 4px（入力中は外 10px）。ドック側は、番号の丸の高さの、カードの左端。**範囲を持たないコメント**（「この対象全体」）は、枠がないので、対象（`.lb-stage`。html-app は `iframe`）の右端の外 6px から引く（本文のブロックと同じ規則）。文など、引く先のないコメントは、引かない。
- **端点は、実測する**：ズーム・移動・ドックのスクロール・窓の大きさ・カードの開閉・枠の増減を、`requestAnimationFrame` に 1 回へまとめて測る（座標を計算で持たない。ドックにタブはない）。
- **重なり**：`#lightbox > .fv-links` は `z-index: 4`（道具〔`.lb-tools`・`.fv-tools`〕は 5）・`pointer-events: none`・`aria-hidden`。線はカードの左端で止まるので、カードの文字に掛からない。**iframe の中へは入れない**（`sandbox`・CSP・橋は不変：F28・F42・F45）。
- **枠にマウスを置くと、ドックのカードと線が光る**（`hoverBox`。今までなかった動作の追加）。**拡大表示を開いている間は、後ろの本文の `#links` を `visibility: hidden`**（線がまぎれるため）。

### 共用部品に切り出した

- 本文の `Connectors.tsx` から、`overlay/linkFrame.ts`（線の組み立て `composeFrame`・カード側の端点・`GAP`・`sideEnd`・`unionBox`）・`overlay/LinksSvg.tsx`（SVG の描画）・`overlay/useLinkFrame.ts`（更新の骨組み）を切り出した。**`connectorPath.ts` は、変えていない**（既存の `Connectors`・`connectorPath` のテストは、そのまま通る）。
- 見た目は、`connectors.css` のセレクターを `:is(#links, .fv-links)` に広げ、色・点線・active／linked／pending／resolved／edge を、本文と共通にした。
- 理由：同じ線を、2 か所で別々に実装すると、見た目と規則（端点・光り方・縁に寄せる規則）が、ずれていく。

### オン・オフは、`ui.links` を共有する

- **`ui.links` をそのまま共有**し、ドックの見出しに、同じボタン（`panel/LinksToggle.tsx`。右パネルのボタンも、これを使う）。拡大表示で切ると、**閉じてもオフのまま**・本文の線も、同じ状態。
- 採らなかった案：拡大表示だけの別の設定を持つ（本文と食い違い、利用者が、どちらがオンか分からなくなる）。

### 窓が 760px 未満は、線を引かない

- 窓が 760px 未満のとき、ドックは、下のシートになる。**右へ引き出して、左のカードへ戻る線は、本文の `connectorPath` の形では描けない**ので、引かない（番号で結ぶ）。1100・900px では、引ける。

### `id` を付けない

- `.fv-links`（クラス）と `zoom-fv-links-clip`：既存の `zoom.spec` が、「`#lightbox` の中の ID は `zoom-` で始まる」ことを確かめている。svg に ID を付けず、`clipPath` の ID は `zoom-` で始め、ドックのボタンも ID なし（`.fv-links-toggle`）。

### `interact/hoverLink.ts` の 2 行の修正

- **`applyLinked` が、文書全体の `.linked` を外していて、React が持つ線のクラスを書き換え**、線の `linked` が、50% ほどの確率で戻らなくなった（e2e で再現）。→ **`svg.fv-links` だけは触らない**ようにし、単体テストを足した（本文の `#links` の挙動は、不変）。

## 見本のデータの問題（利用者の報告の調査）

利用者の報告「画像の選択が範囲選択おかしい」「図についてはなぜか選択範囲がズレてる」を、調査した。**どちらも、コードの不具合ではなく、見本のコメントのデータの問題だった**。

1. **画像の枠が、見出しの高さの細い帯に描かれる**：見本の `threads.json` の範囲コメントが、`blockId`・`blockHash`・`blockTag`・`blockText` を、**1 つずれた番号**（画像でなく、直前の見出し `b10`・`382p5a`・`H2`・`"x"`）で保存していた。枠が、画像でなく見出しの箱を基準に描かれた（`frameOf(H2)` は、見出し自身を返す）。**`main` のコードは、遅延読み込み・遅い画像・画面の下の画像でも、枠を正しく置き直す**（読み込み前の画像は、幅 0・高さ 0 で、`place.ts` が枠を出さない。読み込み後は、`load` のリスナーと article の `ResizeObserver` で置き直す）。回帰テスト：`e2e/region-lazy.spec.ts`。
2. **図の範囲の枠が、ノードからずれる**：見本の図のコメントの `rect` が、**手で打った丸い比率**（例：Mermaid の「受け取る」が `{0,0.3,0.2,0.4}`。実測は `{0.0094,0.5929,0.1780,0.2286}`）だった。実験（実 Chrome。draw.io のホテル予約と Mermaid の流れ図のノードを DOM から取り、`page.mouse` でちょうど囲んで範囲を選ぶ）では、本文・再読み込み・窓幅 1365／1100／760・ダーク・新しい版・過去の版・拡大表示（作成・表示・ズーム＋移動）のいずれも、枠とノードの差は 0.5px 以内（拡大表示は 0.1px 以内）。回帰テスト：`e2e/range-diagram.spec.ts`。
- **既存データへの影響はない**（範囲の基準は、変わっていない）。

### 決めたこと（範囲の基準とデータの作り方）

- **範囲の基準は、作るときも、表示するときも、描かれた図の `svg`**（本文は `frameOf`・拡大表示はステージの複製）で、**比率は、その矩形に対するもの**。図のブロックの高さは、`svg` より 8px 大きいので、基準が `svg` でなくブロックにずれると、本文と拡大表示で食い違う（今の `frameOf` は、作るときも表示するときも同じ）。
- **図・画像のコメントを API で直接作るときは、ノードの比率を DOM から取り、`blockId` と `blockHash` も、DOM の `data-bid`・`data-bhash` から取る**（丸い数や、決め打ちの番号を使わない）。

## 既知の点

- 範囲コメント（`rect` つき）が、画像・図・html-app でないブロックを指していても、いまは、見出しなどの箱に枠を描く（描かない・API で拒否するかは、別の仕様の判断：変えていない）。
- 拡大表示で、ほかの枠の上を通る水平の引き出し線が、その枠の上に重なって描かれる（本文の線が、文字の上を通るのと、同じ見た目）。
- 並列の負荷で落ちる既知の e2e（`loop.spec`・`focus.spec` の枠内 Esc・`htmlapp-writeback`・`closed-view` の窓幅）がある（単独では通る）。
- 詳細：[docs/verification.md](../verification.md)

## 独立レビュー（2026-11-25。`reviewer`）

- **結果**：Blocker・Major・P2 なし。P3 4 件（対応済み）。実 Chrome で `main` と比べ、本文の線（F35）に退行がないこと（23 の場面を 3 回比べて、違いは、開いている間の `visibility: hidden`〔意図どおり〕だけ）・760px で引き 759px で引かない・開閉 20 回でリスナー・DOM が増えない・安全の面（サーバー・`sandbox`・CSP・橋は不変・`innerHTML` なし）を確認した。
- **P3 と対応**：(1) 枠にマウスを置いたまま Esc で閉じると、本文の光りが残った → `hoverBox` が `tid` を控え、`FocusLinks` が外れるときの `releaseHover` が、まだ同じ `tid` のときだけ戻す（単体 1 件・e2e を足した）。(2) 拡大表示の間に本文の `#links` を隠す規則に、テストがなかった → e2e を 1 件足した。(3) `range-diagram.spec.ts` の拡大表示のテストが、負荷で 60 秒を超えうる → `test.setTimeout(120_000)`。(4) テストの説明の食い違い・`region-lazy.spec.ts` に「読み込み前は枠が 0 個」の確認を足した。
- 再レビューは、受けていない。
