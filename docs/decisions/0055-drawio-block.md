# ADR-0055 draw.io の図（`drawio` コードブロック）：公式ビューアを使わず、自前で XML → SVG に描く

- 日付：2026-11-24
- 種別：AI の設計の判断（0.32.0。RIK-065）
- 関連の機能：[F52](../features/doc-format.md#f52-資料に-drawio-の図を埋め込める)
- 決定の元：[利用者の決定](user-decisions.md)（2026-11-24「マークダウンの中にドロー IO の XML を埋め込んで、それを描画することって可能…」→「対応してみて欲しい」。利用者が、見本で確認して、「問題ない」と承認した）。
- 一覧：[ADR の一覧](README.md)

## 決めたこと

### 公式の `viewer-static.min.js` を使わず、自前で描く

- **公式のビューア（`viewer-static.min.js`）は、使わない**。理由：
  - **外部の資源**：ステンシルなどを、`viewer.diagrams.net` から読むことがある。N1（外へ出さない）と合わない。
  - **サイズ**：バンドルが、大きく膨らむ。
  - **スクリプトの実行**：図の XML を、スクリプトを動かす部品に渡すことになる。N3（資料が、画面で、スクリプトを動かさない）と合わない。
  - **npm の公式パッケージが、ない**。
- **自前で、XML → SVG に描く**：`<mxGraphModel>`（または `<mxfile><diagram>`）を、中間モデルに読み、SVG に組み立てる。**図の判定・拡大・範囲選択・番号・線は、Mermaid の図と同じ経路**で動く（F37・F43・F25・F22）。
- 対応する記法は、典型的なもの（四角・角丸・楕円・菱形・円柱・スイムレーン・表・アクター・生命線・直交の線・矢印の種類・ラベル）。**対応しない記法は、四角で描いて、図の下に知らせる**（失敗にしない）。

### SVG の組み立て方

- **SVG は、`createElementNS`・`setAttribute`・`textContent` だけで組み立てる**。**`innerHTML` は使わない**。`style` 属性・`foreignObject`・`href`・`<image>` も作らない。資料の XML は、非信頼のデータなので、文字として扱い、要素にしない。
- **色は、検査して通す**：`#rgb`・`#rrggbb`・`#rrggbbaa`・`none`・`inherit`・CSS の色名・`light-dark(a,b)` だけ（`rgb()`・`url()` は、出さない。無視した色は、図の下に記録する）。長さが 4000 を超えるスタイルは、超えた分を読まない。
- **上限**：XML 500KB・セル 2000・座標 ±100000・入れ子 25・圧縮の展開後 2MB。超えたら、理由とソースを文字で出す（失敗の表示は、Mermaid と同じ：`.mermaid-error`・`.mm-err`・`pre`）。DOCTYPE・ENTITY は拒否する。
- **圧縮形式**（base64 + deflate-raw + URI エンコード）は、`DecompressionStream` で展開して描く。

### 矢印を `<marker>` でなく、多角形で描く

- **`<marker>` を使うと、図に `id` と `url(#…)` が出る**。拡大表示では、SVG を複製して、`id` に接頭辞（`zoom-`）を付け、参照を書き換える（F37。コーディング指針）。範囲の切り出しでは、SVG を単独の画像にする：どちらも、`id` の参照が壊れうる。
- **多角形で描けば、図に `id` も `url(#…)` も出ない**ので、複製でも、単独の画像でも、壊れない。

### ダークモードの色

- **標準の色は、`var(--dx-ink, #リテラル)` のように、トークンとリテラルを併記する**（`app.css` の `--dx-ink`・`--dx-fill`）。**範囲の切り出し画像は、ページの CSS を持たない**ので、描いた時点の外観のリテラルが入る：外観が変わったら、描き直す。
- **指定した地の上の、色指定のない文字は、地に合わせて、黒か白にする**。
- **純粋な黒の線・文字と、純粋な白の地は、標準の色として扱う**（draw.io のダークモードの反転と同じ向き。ダークで、黒い矢印が消えないように）。**これが、「指定の色は、そのまま」の例外**（ほかの色は、そのまま）。
- 線の上のラベルは、既定で、紙の色の地を敷く（`labelBackgroundColor=none` で外せる）。

### そのほか

- **`.drawio-block` は、ほかのブロックと同じ扱い**（ブロックにマウスを置くと出る「コメント」「拡大表示」も同じ）。
- **`fillDiagrams`**：Mermaid と draw.io を、まとめて描く入口。本文・返信・比べる画面・外観の変更の 4 か所が、これを呼ぶ（`fillMermaid` の export は、既存のテストのために残した）。
- **`drawioRender` は、動的 import**：図のない資料では、読まない（chunk 31.9KB・gzip 13KB。`index.js` は +1,273 B）。

## 採らなかった案

- **公式のビューアを、埋め込む／iframe で隔離して使う**：外部の資源・スクリプトの実行・サイズの問題が、残る。自前の描画なら、N1・N3 を弱めない。
- **draw.io の図を、画像（PNG・SVG のファイル）として、`assets/` に置く**：依頼は、「Markdown の中に XML を埋め込んで描画する」こと。AI が、資料の中で、図を書き換えられ、版の差分にも出る。
- **`<marker>` で矢印を描く**：上のとおり、`id` の参照が壊れる。

## 残る課題

- **本物の draw.io が出す XML は、手元で draw.io を動かせないので、仕様と典型の形から書いて確かめた**：実際のファイルでの確認は、人手が要る。
- 経路は簡易で、他の図形を避けない（複雑な図では、経由点が要る）。見本の色・行間の厳密な再現（行間は、見本が約 1.7 倍・こちらは 1.2 倍。色は測っていない）・曲線・グラデーション・影・`fontFamily` の指定・`<mxfile>` の複数ページ（最初だけ）は、未対応。
- 実際のマウス・他のブラウザ・スクリーンリーダーは、未確認。
