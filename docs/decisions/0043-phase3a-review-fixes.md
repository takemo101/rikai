# ADR-0043 整理フェーズ ③a のレビューの指摘への対応

- 日付：2026-11-24
- 種別：AI の設計の判断（もとは、SPEC.md の §8 の表の 1 行。文言は、そのまま移した）
- 関連の機能：[F48](../features/ui-cleanup.md#f48-名前と状態の言葉と上のバーの整理)
- 決定の元：[利用者の決定](user-decisions.md)（2026-11-24「整理フェーズ ③a の、利用者の決定（整理分析の結果…」）。文中の「上の…」は、この決定を指す。
- 一覧：[ADR の一覧](README.md)・[SPEC.md の §8](../../SPEC.md#8-利用者の判断)

（AI の判断。整理フェーズ ③a の独立レビューの指摘への対応。0.28.0）

- **(1) 取っ手の幅に、`panelUser`（印）を足した**：幅の値だけでは、「既定のまま（380）」と、「利用者が 380 を選んだ」が、区別できない。1100px 以下で、値が 380 なら 280 にする形では、利用者が選んだ 380 が、280 に戻り、ドラッグの途中でも、380 を通る瞬間に、100px 跳ねた。**印は、取っ手の操作で付く**（ダブルクリックは、既定に戻すので消す）。**データの形（`localStorage` の `rikai-ui`）の拡張**だが、サーバー・`.rikai/` には関わらない。**古い保存**（印なしの 380）は、「既定」と見なす：古い保存の利用者が、1100px 以下で、280 になる変化は、意図した（0.28.0 の、既定の変更）。
- **(2) `#docbar` に、コンテナクエリを使わなかった**：`container-type` は、`position: fixed` の子孫（拡大表示・行動バー・トースト）の基準を変える副作用がありうる。折り返しを許す `flex-wrap: wrap` と、先に縮む欄（最小幅つき）で足りるので、使わなかった。**枠の見出し（`.cap`）には使った**（子孫に `position: fixed` がなく、見出し自身の幅で、省略を決める必要があった：本文の枠の幅は、窓の幅と無関係）。
- **(3) 過去の版の警告を、約 100px まで縮める**：1360px・パネル 380 で、1 行に収めるため。全文は、`title`（取りこぼしを避けるため、折り返しも許す）。
- **(4) 中身が空の `#docbar` は、`hidden`**：版が 1 つのルートページでは、40px の空の帯が、本文の上に残っていた（ID は、CSS・e2e が使うので残す）。
- **(5) 拡大表示の道具の帯は、折り返さず、「×」を常に上の行の右端に**：「×」が 2 行目に落ちると、閉じる場所が、窓の幅によって動く。
- **(6) 見送った**：枠の幅が 200〜300px 台のときの、見出しの 95〜119px（説明の文言を短くする判断が要る）・過去の版の警告の、さらなる短縮（[検証記録](../verification.md)）
