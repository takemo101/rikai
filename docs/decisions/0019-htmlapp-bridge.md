# ADR-0019 html-app の橋（段階 1）

- 日付：2026-11-23
- 種別：AI の設計の判断（もとは、SPEC.md の §8 の表の 1 行。文言は、そのまま移した）
- 関連の機能：[F40](../features/html-app.md#f40-html-app-の枠と画面をつなぐ橋)
- 決定の元：[利用者の決定](user-decisions.md)（2026-11-23「html を強化していく。デザインの比較・UI のレ…」）。文中の「上の…」は、この決定を指す。
- 一覧：[ADR の一覧](README.md)・[SPEC.md の §8](../../SPEC.md#8-利用者の判断)

（AI の判断。上の方針の範囲。0.21.0）**html-app の橋**（F40。段階 1）：**橋は、枠 → 画面の `resize`（高さ）と、画面 → 枠の `theme`（外観）の 2 種類だけ**（`postMessage`。画面の DOM・コメント・保存には触れない）。**画面の側は、送り元の窓（`e.source`）で検査する**（sandbox の枠は、オリジンが `null` なので）。値は、形・数・上下限〔120〜2400px〕・頻度〔1 つの枠につき 1 秒に 6 回〕を確かめる。**土台のスタイルは、すべて `:where()`（詳細度 0）**にして、AI の CSS が、つねに勝つようにした（従来の資料の見た目を、できるだけ変えない）。**既定は自動の高さ**（`height=` なし）。`height=N` は、従来どおり固定。**従来の資料への影響**：ダークで、背景色だけを書いた資料が読めなくなることがある（枠だけをライトにできる）。**「ダークでも、枠は常にライト」（F36 (8)）を、「枠は、画面の外観に従う」に変えた**（デザインの比較のため）。**`APP_CSP` と、`sandbox` の内容は、変えない**。揺れ防止は、報告の間隔・往復の検出・`100vh` ＋余白の循環の検出で行う。1280・1920 の幅は、本文の幅（最大 760px）が上限（デスクトップの幅そのものは、段階 3 以降の課題）（[検証記録](../verification.md)）
