# ADR-0022 ブラウザの通知にした

- 日付：2026-11-23
- 種別：AI の設計の判断（もとは、SPEC.md の §8 の表の 1 行。文言は、そのまま移した）
- 関連の機能：[F41](../features/turn-notify.md#f41-確認すべきイベントをブラウザの通知で知らせる)
- 決定の元：[利用者の決定](user-decisions.md)（2026-11-23「資料の更新・AI の返信など、確認すべきイベントが起…」）。文中の「上の…」は、この決定を指す。
- 一覧：[ADR の一覧](README.md)・[SPEC.md の §8](../../SPEC.md#8-利用者の判断)

（AI の判断。上の依頼の範囲。0.22.0）**ブラウザの通知にした**（F41）：**全 OS 共通の `Notification` API**。画面が SSE〔F38〕で更新を受けたとき、画面を見ていなければ出す。**Web Push は採らない**：ブラウザの会社の Push サービス〔外部〕を経由するので、N1〔通信は 127.0.0.1 だけ〕に反する。**サーバーからの OS 通知は見送った**：OS ごとの実装になり〔macOS は `osascript`・Linux は `notify-send`・Windows は PowerShell〕、macOS は動くことを確かめたが、Linux・Windows は確かめられない（将来、タブを閉じていても届く通知が必要なら、再検討：§7）。**既定はオフ**（押す操作で許可を求める：許可の求めを、利用者の操作に結びつける）。**画面を見ているときは出さない**。**新着は、ID の比較で決める**（件数の差だと、読んだあとに来た返信を洩らし、解決の取り消しで誤って出す：独立レビューで分かった）。**累計にした**（画面を見ていない間に溜まった合計を、同じ `tag` で置き換えて出す：通知が積み上がらない。画面が見える状態に戻ったら 0）。**内容は、トピック名と件数だけ**（AI の本文・資料の中身は載せない：N6。トピック名は、制御文字・双方向文字の制御を除いて、40 コードポイントで切る。`icon` は、0.22.0 では付けなかった：外のものを読まないため。0.23.1 で、rikai の PNG の `data:` だけを付けた：下の行）。**対象は、開いているトピックだけ**（F39 と同じ制約）。サーバー・CLI・HTTP・データの形式は、変えない（[検証記録](../verification.md)）
