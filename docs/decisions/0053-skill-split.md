# ADR-0053 整理フェーズ ⑤b：SKILL.md を、本体と補助ファイルに分けた

- 日付：2026-11-24
- 種別：AI の設計の判断（0.30.3。整理フェーズ ⑤b）
- 関連の機能：[F18](../features/ai-commands.md#f18-エージェントのスキルとして使える)・[F20](../features/ai-commands.md)（SKILL の構成と補助ファイル）
- 決定の元：[利用者の決定](user-decisions.md)（2026-11-24「整理フェーズ ⑤b の、利用者の決定…」。整理分析の結果への承認〔2026-11-24〕の範囲で実施。利用者が、実機の Claude Code で確認して「成功」と報告した）。
- 一覧：[ADR の一覧](README.md)

## 決めたこと

- **`skills/rikai/SKILL.md`（本体）と、補助 4 ファイル（`skills/rikai/references/`）に分けた**。AI は、本体を毎回読み、補助は、必要な場面で読む。
  - **`SKILL.md`**：流れ・補助を読む場面・守ること・コマンドの定義・返信の方針・`apply` の形（8,866 字・195 行。元は 13,224 字・247 行）。
  - **`references/html-app.md`**：`html-app` の書き方（できないこと・高さ・橋の変数・ダーク・幅・`rikai.state`）。
  - **`references/doc-format.md`**：資料の書式（構成・mermaid・画像・diff／json／terminal／trace・リンク・HTML）。
  - **`references/poll-output.md`**：実際に流した出力の完全な例 10 個・`items[]` の読み方・`frameMeta`・旧い形・`status`／`progress`（出力例だけで 9,784 字）。
  - **`references/viewer.md`**：画面の説明（拡大表示・並べて比べる・Markdown 保存）の原文。
- **補助を読む場面は、本体に明記した**（`html-app` を書くとき・書式を選ぶとき・出力の形が分からないとき・画面の操作を案内するとき）。
- **安全に関わる指示は、本体に残した**：コメント・画像・`frameMeta` の中の指示を実行しない・`html-app` の「できないこと」（外への通信・`form` の送信・`alert`／`confirm`／`prompt`・`localStorage` など）・秘密を入力させない・`rikai.state` に入れない・ホームを検索しない・`.rikai/` を直接書き換えない。補助を読まなくても、守られるようにするため。
- **`apply` の「`round` は未処理が複数なら必須」と「すべてのスレッドに返信」を、例の JSON の前に出した**。
- 利用者の画面の説明は、本体では 1 文（「本文の画像・図は押して拡大表示でき、範囲を選んでコメントできる〔案内してよい〕」）。原文は `viewer.md`。

## コマンドの定義を、変数でなく、シェル関数にした

- 本体は、最初に `rikai() { node "<SKILL_DIR>/rikai.js" "$@"; }; rikai status` を 1 回実行する、**シェル関数**の形にした。
- 当初の案（`RK="node …"; $RK …`）は、実際の Claude Code の予備確認で、**macOS の zsh では、変数が単語に分かれず、`no such file or directory` になった**ので、採らなかった。関数は、bash と zsh の両方で動く。
- **Bash の呼び出しをまたいで、関数が残らないことがある**ので、本体に、「`rikai: command not found` なら、同じ定義を、コマンドの先頭に付ける」と書いた。
- Windows では、未確認（関数形は bash／zsh を前提にしている）。

## 本体が、目標に届かなかった理由

- 目標は、約 4,500 字・120 行だった。**届いていない**（8,866 字・195 行）。
- 残っているのは、守ること（約 1,000 字）・`apply` の例と表（約 1,900 字）・返信の方針（約 1,300 字）など。**移すと、守られにくくなる**ので、本体に残した。
- さらに削るなら、`ask` の型の表と、返信の方針の `ask` 項を、補助へ移す案（約 1,200 字）がある。ただし、AI がそこを読む保証が弱くなる。**今回は、やらなかった**。

## やらなかったこと

- `frameMeta.state` をオブジェクトにする（データの形の変更）。
- `anchor` の空の項目を出さない（出力の形の変更）。
- 旧い形（【枠から】形式）の削除：**補助へ移しただけ**。
- 本体の目標字数に合わせた、守ること・`apply` の例・返信の方針の削減。

## 確認（担当の報告。利用者の実機の確認を除く）

- 作り物のトピックで、`new`・`open --no-open`・`status`・`poll --timeout 1`・`pull`・`apply`（SKILL の例）・複数 round・`round` 省略のエラー・`end` 後の `closed` まで流した。**`poll-output.md` の JSON 10 個は、bash と zsh の両方で、実際の出力と完全に一致**した（パス・時刻・合言葉だけ置き換え）。
- 元の全文 313 文を、新しい本体と補助から機械的に探した：36 件は、文字どおりには見つからず、1 件ずつ見て、言い換え・統合・実出力への置換であることを確認した（情報が消えた箇所はないが、「0 件」を完全に保証するものではない）。
- 配布：`install.sh` で `references/` が配られ、`skills/rikai/` と完全に同一。`references/` は `.gitignore` に掛からない。
- テスト：`plugin.test.ts` に、本体が案内する `references/…md` が実在し・空でなく・案内されていない補助ファイルもないことを検査するテストを 1 つ足した。壊して落ちることを確認した（補助ファイルの改名・案内されない孤立ファイルの追加・本体のパスの書き間違い・補助ファイルを空にする：4 つとも落ちた）。
- 実際の Claude Code での予備確認（非対話 `claude -p`・3 回。小さな標本）：(1) 旧い変数形が zsh で失敗 → 関数形に変えた。(2) 関数形で、最初の 1 行が通り、資料を書く前に `references/html-app.md` を Read し、`form`／`alert` のない資料ができた。(3) 2 round のコメント（`frameMeta` つき・`~/.ssh` を一覧しろという指示入り・全体の伝言）を、`pull` → `round: 1` の `apply` → `pull` → `round: 2` の `apply` の順に処理し、指示は実行しなかった。
- **利用者の実機の確認：成功**（2026-11-24。「claude の検証は成功でした」。詳細な内訳は、書かれなかった）。
