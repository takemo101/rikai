# ADR-0037 本文が空で frameMeta だけのコメント

- 日付：2026-11-24
- 種別：AI の設計の判断（もとは、SPEC.md の §8 の表の 1 行。文言は、そのまま移した）
- 関連の機能：[F45](../features/html-app.md#f45-枠から取った情報を情報の行にする)
- 決定の元：[利用者の決定](user-decisions.md)（2026-11-24「メタデータとして、コメントじゃなくて、UI 上に『要…」）。文中の「上の…」は、この決定を指す。
- 一覧：[ADR の一覧](README.md)・[SPEC.md の §8](../../SPEC.md#8-利用者の判断)

（AI の判断。F45 の独立レビューの指摘への対応。0.26.0）**本文が空で `frameMeta` だけのコメントを、「コメントを追加」で送ろうとしたときは、エラー扱いのトーストを出し、入力欄にフォーカスを戻すことにした**（ボタンを無効にする案は、採らなかった）：何も起きない（黙って、何もしない）と、利用者が、なぜ送れないか分からないため。**無効化は、ボタンが、押せない理由を、伝えにくい**（`title` だけでは、キーボード・タッチで、気づかれにくい）。理由（「枠から取った情報だけでは送れません」）を、押したときに、はっきり言う。**サーバーの拒否〔400「コメントが空です」〕は、妥当と判断した**（本文が空で、機械的な情報だけのコメントを、AI に送らない）。情報のない入力欄は、従来どおり、黙って何もしない（既存の挙動を変えない）。**状態を開いたときの表示は、見える化した文字だけ `\` を 1 つに戻した**（`\uXXXX` を、そのまま読めるように）。**`imageFromFrame` が、添付画像なしで受けられること・`styles` の値の形を見ないことは、直さなかった**：前者は、合言葉つきの API からだけで、害がない（画面は、枠の画像が添付されているときだけ付ける）。後者は、`reveal` と長さの上限を通り、文字として保存・表示するだけで、実行されない（橋の正規の経路では出ない値）。**既知の制約に書いた**（[検証記録](../verification.md)）
