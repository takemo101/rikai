# ADR-0036 F45 の設計

- 日付：2026-11-24
- 種別：AI の設計の判断（もとは、SPEC.md の §8 の表の 1 行。文言は、そのまま移した）
- 関連の機能：[F45](../features/html-app.md#f45-枠から取った情報を情報の行にする)
- 決定の元：[利用者の決定](user-decisions.md)（2026-11-24「メタデータとして、コメントじゃなくて、UI 上に『要…」）。文中の「上の…」は、この決定を指す。
- 一覧：[ADR の一覧](README.md)・[SPEC.md の §8](../../SPEC.md#8-利用者の判断)

（AI の判断。上の依頼の範囲。0.26.0）**F45 の設計**：

- (1) **Zod を使わず、手書きの `parseFrameMeta` ＋ HTTP の本体は `z.unknown()`**：画面に Zod を入れない規約（F42）に従い、画面とサーバーで、同じ関数を共有する。他の項目と同じ流儀。
- (2) **`state` を、JSON の文字列にした**：入れ子の型にすると、Hono の応答の型と `Thread` の型が、互いに代入できなくなるため。AI は `JSON.parse` して読む。
- (3) **サーバーも検査する**（画面を信頼しない）：画面を通らない POST で、余分なキー・巨大な値・`__proto__`・見えない文字を、送れてしまうため。不正は 400・16KB 超は 413・値はメッセージに含めない・何も書かない。**長さは、見える化した `\uXXXX` を 1 文字と数えて測る**。
- (4) **本文が空で `frameMeta` だけのコメントは、拒否する**：本文が空の、機械的な情報だけのコメントを、AI に送らないため（挙動が変わる：F42 は、JSON が本文に入っていたので、書かずに送れた）。
- (5) **「枠から」の札は、`frameMeta` の有無で付ける**（偽造できない）：旧い判定（本文の見出し行）は、旧いコメント専用。**残る隙**：`frameMeta` なしのコメントで、枠のブロックを指す錨に、旧い見出しの全文を、手で書くと、札が付く（旧いコメントを読むために、残している）。
- (6) **カードの行の中の札は出さず、見出しの札だけにした**（古いやり取りを折りたたんでも、札が残る）。
- (7) **「外す」は、画像の印だけ外し、画像は残す**（添付の画像は、利用者の持ち物のため。錨・本文も残す）。
- (8) **新しい `pick` は、古い `pick` を置き換える**（トーストで知らせる）。**枠の情報を持つ入力欄から、情報のない対象へ移るときも、トーストで知らせる**（情報が、消えたことに、気づけるため）。
- (9) **入力欄は、空で開く**（書きかけの文は残す）：本文に、何も書き込まない。
- (10) **下書き〔`frameMeta` を含む〕は、メモリだけ**（`localStorage` に保存しない：F5・F44 と同じ）（[検証記録](../verification.md)）
