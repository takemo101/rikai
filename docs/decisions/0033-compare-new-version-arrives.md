# ADR-0033 比べている間に新しい版が届いたとき

- 日付：2026-11-24
- 種別：AI の設計の判断（もとは、SPEC.md の §8 の表の 1 行。文言は、そのまま移した）
- 関連の機能：[F44](../features/versions.md#f44-版を並べて比べる)
- 決定の元：[利用者の決定](user-decisions.md)（2026-11-23「一旦全ての依頼の実装を全て進めてほしい。明日朝あたり…」）。文中の「上の…」は、この決定を指す。
- 一覧：[ADR の一覧](README.md)・[SPEC.md の §8](../../SPEC.md#8-利用者の判断)

（AI の判断。F44 の再レビュー〔`main` 0.25.0〕の指摘への対応。0.25.1）**比べている間に新しい版が届いたときは、入力欄の対象を、新しい版の本文で探し直し、見つかれば続け、見つからなければ、別の対象に付けず、「対象を失った下書き」にした**：探し直しは、コメントの位置づけの既存の仕組み（`markPending`：`findQuote`・`locateBlock`。F12）を使う（探し方を 2 通り作らない）。**見つからない書きかけを、次に開く入力欄に入れない**：入れると、利用者が気づかないまま、別の対象のコメントとして Submit され、範囲の画像も、別のコメントに付くため。**「対象を失った下書き」は、メモリだけにした**（`localStorage` に書かない）：ほかの書きかけ（ask の選びかけ・返信欄の入力・入力欄の文）が、メモリだけなのと揃え、文を、ブラウザに残さない。**パネルの上に、1 件だけ、注記つきで出し、利用者が、コピー・破棄を選ぶ**（文は、勝手に消さない：利用者が書いた文のため）。画像は、コピーできないので、枚数だけ出す。別のページ・トピックへ移って閉じたときも、同じ扱い（対象を戻せない）。**比べる画面を開いていないときの、入力欄を開いたまま新しい版が届く場合は、変えていない**（従来どおり、入力欄と文が閉じて消える：F11・F12 の既存の扱い。別の作業）（[検証記録](../verification.md)）
