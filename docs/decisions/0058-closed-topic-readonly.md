# ADR-0058 終了したトピックは、全面の終了画面をやめて、閲覧専用で見られるようにした

- 日付：2026-11-25
- 種別：AI の設計の判断（0.1.4）
- 関連の機能：[F54](../features/topics-pages.md#f54-終了したトピックを閲覧専用で見られる)・[F16](../features/topics-pages.md#f16-レビューを終えられる)・[F34](../features/topics-pages.md#f34-終了の確認は画面のダイアログで行う)
- 決定の元：[利用者の決定](user-decisions.md)（2026-11-25「終了したトピックって中見れないの？ 終了してもコメントはできないけど、中身は見れるようにして欲しい」）。
- 一覧：[ADR の一覧](README.md)

## 決めたこと

### 全面の終了画面をやめて、帯つきの閲覧専用にした

- **全面の終了画面（`EndedScreen`・`#ended`）を、削除した**。終了したトピックも、本文・ページ・版・変更の見せ方・並べて比べる・拡大表示・Markdown の保存・スレッドの閲覧が、そのまま使える。
- **上に帯 `#closedbar`**（`layout/ClosedBar.tsx`）：「このトピックはレビューを終了しています（閲覧専用・コメントできません）」。`View.readOnly` を、`buildView` が `meta.closed` から導く。
- **帯の置き場所は、`#doc`（本文の列）の先頭で、`#docbar` の上**。`#top`・`#docbar` には、入れない：文を足すと、状態の札・「AI に送る」・版の切り替えが押し出されるため（「終了」の前後で `#top` の高さが同じことを、e2e で確認）。1360・1100px では 1 行。420px は、本文の列が約 200px なので、3〜5 行に折り返す（横にはみ出さない）。
- **書く入口は、出さない（または無効）**：文を選ぶ「コメント」・「範囲を選ぶ」・html-app の「要素を選ぶ」「この枠にコメント」（拡大表示内の枠も）・拡大表示のドックの入力欄と道具（ドックには「ここでは、読めます」）・右パネルの入力欄・返信欄・追加・解決・再開・編集・削除・画像添付・「終了」ボタン。質問への回答は、選択肢を押せない表示（保存・取り消し・「答える」は出さない）。「AI に送る」は、未送信があっても無効（理由は「このトピックは、終了しています」）。未送信の下書きは、見えるが、編集・削除はできない。**「終了」を押した瞬間に、途中だった入力欄の対象・範囲選択・要素選択は外す**（`useReadOnlyEffects`）。読む操作は、動く。

### サーバーも、書き込みを拒否する（409）

- **`comment`・`reply`・`answer`・`edit`・`delete`・`resolve`・`submit`・`attach` の 8 つ**すべてで、ロックの下の `meta` を見て、`HttpError(409)`。**以前は、終了後でも、8 つとも通っていた**（`poll.test` の「終了後に submit」が通る形だった）。画面の入口を消すだけでは、API を直接呼べば、書けてしまう。`end` の再送は、200 のまま。
- 理由：**閲覧専用の保証は、サーバーが持つ**（画面は、入口を出さないだけ）。ロックの下で見るのは、`end` と書き込みが競合しても、終了後に書き込みが通らないようにするため。

### サーバーの寿命を、「すべて閉じて、待ち時間リクエストなし」にした

- 以前は、「すべてのトピックが閉じたら、約 800ms 後に終了」。**終了したトピックを閲覧できるようにすると、閉じた直後にサーバーが落ち、画面が見えなくなる**。
- **「すべて閉じて、かつ、待ち時間のあいだ、リクエストがない」とき、終わる**（`serve.ts` の `createIdleWatch`。既定 10 分。環境変数 `RIKAI_IDLE_MS` で、試験のために短くできる）。タイマーは `unref`・リクエストのたびに延びる・起動直後と `end` で始まる。**SSE の購読が開いている間は、終わらない**（`busy`：タブが開いている）。待ちが過ぎたとき、開いているトピックがあれば、何もせず待ちを解く（次のリクエストで、また始まる）。
- `rikai new`・`rikai open` も、疎通確認のリクエストを送るので、開いているトピックができれば、終わらない。`rikai stop` は、そのまま効く。`poll` の `closed` と、「開き直すと見える」は、変えない。
- 採らなかった案：**サーバーを、終了後も常に生かす**（プロセスが残り続ける）。**待ち時間を短くする**（閲覧中に落ちる）。

### `rikai open <topic> --view` を足した

- **`meta.closed` を変えずに**、サーバーを起動して URL を出す（出力の形は同じ）。開いているトピックに付けても、これまでどおり、開くだけ。`BOOLEAN_FLAGS` に `view` を足し、ヘルプ（全体と `open --help`・`serve` の説明）と README を直した。
- **`rikai open <closed>`（フラグなし）は、これまでどおり、開き直す**（コメントをまた書ける）。
- 理由：「開き直す」と「見るだけ」を、取り違えないため。フラグなしの動きを変えると、既存の使い方（SKILL.md）が変わる。`SKILL.md` は、「見せるだけなら `--view`」の 1 文だけ足した。

## 残る課題

- 帯は、420px で、数行に折り返す（本文の列そのものが狭いため）。
- `rikai open <closed> --view` で起動したサーバーは、誰も来なければ、10 分で終わる。
- 実際のマウス・他のブラウザは、未確認。
- 詳細：[docs/verification.md](../verification.md)
