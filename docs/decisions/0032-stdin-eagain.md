# ADR-0032 大きな標準入力の EAGAIN の修正

- 日付：2026-11-24
- 種別：AI の設計の判断（もとは、SPEC.md の §8 の表の 1 行。文言は、そのまま移した）
- 関連の機能：[F1](../features/ai-commands.md#f1-トピックを作れる)・[F8](../features/ai-commands.md#f8-ai-が-1-回の入力で返信と修正を反映できる)
- 決定の元：[利用者の決定](user-decisions.md)（2026-11-23「一旦全ての依頼の実装を全て進めてほしい。明日朝あたり…」）。文中の「上の…」は、この決定を指す。
- 一覧：[ADR の一覧](README.md)・[SPEC.md の §8](../../SPEC.md#8-利用者の判断)

（AI の判断。F44 の独立レビューで見つかった、前からある不具合）**大きな標準入力の `rikai new`・`rikai apply` が `EAGAIN` で失敗した**（18 万バイト以上のパイプ・ヒアドキュメント。`< file` は成功。大きな資料の `apply` が、AI にできなかった）→ **標準入力を、ストリームで、バイトのまま集めて、1 度だけ UTF-8 にした**（`fs.readFileSync(0)` をやめた。チャンクの境目で、日本語・絵文字が割れない）。**コマンド・入力の形・データの形は、変えない**（F1・F8）。F44 とは別の不具合だが、同じレビューで見つかったので、同じ版（0.25.0）で直した（[検証記録](../verification.md)）
