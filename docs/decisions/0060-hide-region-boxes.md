# ADR-0060 範囲の枠を、一括で隠せるようにした。html-app の見出しの注意文は、見える文字をやめ、`title`・`aria-label` に残した

- 日付：2026-11-25
- 種別：AI の設計の判断（0.1.6）
- 関連の機能：[F56](../features/region-element.md#f56-範囲の枠を隠せる)・[F31](../features/region-element.md#f31-範囲の枠の調整と添付画像の拡大)・[F28](../features/html-app.md#f28-資料に実行できる枠-html-app-を書ける)・[F43](../features/zoom.md#f43-個別表示でコメントする)・[F55](../features/zoom.md#f55-拡大表示でも関連の線で結ぶ)
- 決定の元：[利用者の決定](user-decisions.md)（2026-11-25 (A)「html-app の場合、コメント枠がついていると、そもそもクリックなどの操作の邪魔になることがあるので、これ非表示にするモードがあってもいいですね」(B)「この表示は必要ないです」〔html-app の枠の見出しの上の「実行できる枠 1（隔離されています。パスワードなどの秘密は、入力しないでください）」〕）。
- 一覧：[ADR の一覧](README.md)

## 不具合の測定（実 Chrome）

`elementFromPoint` と本物のマウスの click・入力・ホイールで、範囲コメント 3 つが重なる枠を用意して測った。

| 枠 | 枠の中の操作 |
| --- | --- |
| 本文の保存済み `.regionbox`（`pointer-events: none`） | 届く（問題なし） |
| 本文の入力中の枠 `.regionbox.pending` | **全部届かない**（F31 の調整のハンドルのため `pointer-events: auto`。設計どおりだが、枠の中を塞ぐ） |
| 拡大表示の保存済み `.fv-box` | **全部届かない**（クリックでスレッドを選ぶため `pointer-events: auto`。**依頼の実害の本体**） |
| 拡大表示の入力中の `.fv-box.pending` | 届く |

番号の丸・関連の線は、問題なし。

## 決めたこと

### (A) 範囲の枠を、1 つのボタンで、すべて隠す

- 状態 `ui.regionBoxes`（既定 `true`。`ui.links` と同じく `rikai-ui` に保存し、リロード後も維持）。
- **対象は、本文の `.regionbox` と拡大表示の `.fv-box`：画像・図・文・html-app のすべての範囲の枠**。採らなかった案：html-app の枠だけ隠す（同じ層の枠が、隠れたものと出たものとで混在し、分かりにくい）。要素コメントは枠を持たないので、対象外。
- **隠し方は、DOM に置かない**（本文は `place.ts`・拡大表示は `useFocusCtx` の `regions` で絞る）。採らなかった案：CSS で `display: none`（絞る場所が 2 つに割れ、枠が残っている前提のコードが壊れにくい利点より、DOM に出さない単純さを取った）。関連の線は、端点の枠がないので、自動的に消える。**番号の丸・カードは、そのまま**（丸の高さも同じ）。
- **ボタンの置き場**：右パネルの見出し（`#regions-toggle`。「関連の線」の隣・`.panel-h-tools`）と、拡大表示のドックの見出し（`.fv-regions-toggle`・`.fv-dock-tools`）。クリック数が増えず、**`.cap` には足さない**（すでに 5 組のボタンと折り返しがあり、狭い窓で崩れやすい）。目のアイコン（Eye／EyeOff）・`aria-label="範囲の枠を隠す"`（名前は固定。状態を名前に入れない：F35 の規則）・`aria-pressed`＝隠している・`title` にいまの状態。
- **入力中の枠（pending）は、隠している間も、押せない破線で残す**（`.regionbox.pending.still`・ハンドルなし）。理由：枠を隠したまま範囲を選ぶと、何を選んだか分からない。枠の中の操作は塞がない。拡大表示の pending は、元から押せない。
- 終了したトピック（閲覧専用：F54）でも、同じボタンが効く。

### (B) html-app の見出しの注意文は、見える文字をやめ、`title`・`aria-label` に残す

- **`.cap` の文字を空にした**（`markdown.ts`）。**安全の注意（N3：「隔離されています。パスワードなどの秘密は、入力しないでください」）は、`apps.ts` が見出しの行（`.cap`）に `role="group"`・`aria-label`・`title` として付ける**：読み上げとホバーで、失わない。比較画面は、見出しに道具がないので、iframe の `title` に持たせる（`左の実行できる枠 1（隔離…）`）。拡大表示は、元から注意文がない。名前・注意文は、`htmlapp/appName.ts` に 1 か所で定義する。
- 理由：利用者が「必要ない」と決めた。ただし、安全の不変条件（N3：枠に入力した文字は外へ出せる）の伝え方は、見える文字に頼らず、読み上げとホバーに残した。SKILL.md（AI に秘密を求めさせない）と README（利用者に秘密を入力しないよう書く）は、事実が変わらないので、そのまま。

### 文字列への依存の洗い出し

- **壊れなかったもの**：`blockText`・`plainText`・ハッシュ・`textIndex`・`blockLabel` は、ソース（`data-src`）か固定の文字を使い、`.cap` の文字を見ていない（旧い見出しを再現した単体テストで、blockHash・blockId・anchor が変わらないことを確認した）。
- **壊れたもの**：`textOfBlock`（範囲の名前を作る）だけが、ブロックの `textContent` から作っていた → html-app は `実行できる枠 N` を返すようにした。

### 既存コメントの旧ラベル

- 旧いコメントの範囲の名前（`範囲：実行できる枠 2（隔離されています。パスワードなどの秘密は…`）：**保存データは変えない**。表示だけ、`quoteOf` が注意の部分を除く（`stripAppNotice`）。**AI に届くラベルは、旧いコメントでは、旧いまま**（`.rikai/` を書き換えない）。

## 既知の点（残る課題）

- 表示中の拡大表示でも、`.fv-box` は、枠の中の操作を塞ぐ（「隠す」で回避する設計。表示中の動作は、変えていない）。要望があれば、枠を押せなくして、番号の札だけ押せるようにする案がある。
- 表示中の本文の入力中の枠（調整のため押せる）も、同様に塞ぐ。隠している間は、入力中の枠の調整（F31）ができない（枠を出してから調整する）。
- 旧ラベルは、AI に届く側では、注意文入りのまま（表示のみ除去）。
- 実際のマウス・他のブラウザ・スクリーンリーダーは、未確認。
