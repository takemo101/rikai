# ADR-0045 添付の拡大表示を、ドックなし・見るだけにした

- 日付：2026-11-24
- 種別：AI の設計の判断（もとは、SPEC.md の §8 の表の 1 行。文言は、そのまま移した）
- 関連の機能：[F49](../features/ui-cleanup.md#f49-拡大表示の統一と上のバーの切り替え)
- 決定の元：[利用者の決定](user-decisions.md)（2026-11-24「整理フェーズ ③b の、利用者の決定（動く見本で、1…」）。文中の「上の…」は、この決定を指す。
- 一覧：[ADR の一覧](README.md)・[SPEC.md の §8](../../SPEC.md#8-利用者の判断)

（AI の判断。上の決定の範囲。0.29.0。整理フェーズ ③b）

- **(1) 添付の拡大表示を、ドックなし・見るだけにした**：添付は、本文のブロックでなく、範囲・要素を付ける先がない。別のページ・版の画像のスレッドを、ドックに出すのも、不自然。返信の中の画像が、すでにステージだけで開く経路を、そのまま使えば、新しい仕組みが要らない。
- **(2) ドックの中の添付は、ドックの上に重ねて開く（1 段）**：以前は、押しても何も起きなかった。ドックを閉じて、添付を開くと、ドックの下書きが、見えなくなる。**重ねるのは、1 段だけ**（Esc でドックに戻る）：2 段以上は、戻り方が複雑になる。
- **(3) C3 の見えない違い 2 点を、許容した**：比べる間、入力欄の DOM が、隠れて存在する（以前は、存在しない）・比べる画面のまま「過去の版」へ戻ると、下書きが、すぐ「過去の版にあります」の理由で「対象を失った下書き」へ（以前は、閉じたとき「別のページにあります」）。**見える動き（閉じたときに、入力欄が戻る・対象を失った下書きが出る）は、同じ**。引き換えに、`closeCompare` が、約 24 行 → 3 行になり、比べているときと、いないときで、版が変わったときの扱いが、同じ 1 つの経路（`moveComposer`）になった。
- **(4) 画像クリックの統一**：拡大の開く・開かないを、コメントの有無で、変えない。コメントは、右のパネルのカード・拡大表示のドックから開ける（画像・図のクリックで、コメントを選ぶ動きは、なくした）。画像以外のクリックは、変えない。
- **(5) 名前は、改名しなかった**：`#lightbox`・`ui.lightbox` は、改名すると約 300 行のテストに触れる（F48 の対応表のとおり）。
- **(6) 残した課題**：添付のサムネイルの `tabindex`（キーボードで開けない）・ドックの上に重ねた添付から戻ったときの、ズームの位置・ドックの中の `html-app` の状態（[検証記録](../verification.md)）
