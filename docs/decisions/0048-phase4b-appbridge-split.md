# ADR-0048 整理フェーズ ④b：appBridge の分割

- 日付：2026-11-24
- 種別：AI の設計の判断（もとは、SPEC.md の §8 の表の 1 行。文言は、そのまま移した）
- 関連の機能：[F40](../features/html-app.md#f40-html-app-の枠と画面をつなぐ橋)
- 決定の元：[利用者の決定](user-decisions.md)（2026-11-24「整理フェーズ ③b の、利用者の決定（動く見本で、1…」）。文中の「上の…」は、この決定を指す。
- 一覧：[ADR の一覧](README.md)・[SPEC.md の §8](../../SPEC.md#8-利用者の判断)

（AI の判断。整理フェーズ ④b。RIK-060）**移動だけにした**：`web/doc/appBridge.ts`（460 行）を、振る舞いを変えずに、5 つのファイルに分ける。**本体を 1 文字も変えない**（手を入れるのは、他のファイルから使うための `export ` の前置き・import・先頭コメントの配り直しだけ）。

- **(1) クロージャの内側は、分けなかった**：「書き戻し」「要素選択」の受け取り（`receive` の中の `pick`・`state`・`esc`・`snapshot`）は、`registerFrame` のクロージャの内側にあり、分けるには、本体を書き換える必要がある。**移動と論理の変更を混ぜない**ので、`frameBridge.ts` に残した（`framePick.ts` には、クロージャの外にある選択モードの関数だけ）。
- **(2) 旧ファイル `appBridge.ts` は、消した。再公開はしない**：呼び出し側の import を、新しい場所へ書き換えた（`src` 15 ファイル・テスト 8 ファイル）。再公開を残すと、旧い名前が、いつまでも生きる。
- **(3) `FrameHost`（枠のホストを 1 つの部品にまとめる案）は、見送った**：`memory`（`frameState.ts` から export した可変の `Map`）を `registerFrame` が書く・`snapshotSeq` を `registerFrame` 内で増やす、という結びつきの整理は、論理の変更になる。
- **(4) テストは、分割せず、名前だけ変えた**（`appBridge.test.ts` → `frameBridge.test.ts`。共通の準備を別ファイルに出す必要があり、「テスト名・内容は変えない」に反するため）。
- **(5) 独立レビューは、受けない**：移動だけで、本体が同一であることを、行ごとに照合して確認した（元の 31〜460 行のうち、空行でない全行が、新しいファイルに、連続した部分文字列として、そのまま入っている：取りこぼし 0 行）。親も、別の照合で確認する。壊して、落ちることを、5 か所で確かめた（[検証記録](../verification.md)）
