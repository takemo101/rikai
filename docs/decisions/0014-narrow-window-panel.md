# ADR-0014 狭い窓で右パネルの幅を自動で狭くする

- 日付：2026-11-23
- 種別：AI の設計の判断（もとは、SPEC.md の §8 の表の 1 行。文言は、そのまま移した）
- 関連の機能：[F23](../features/appearance.md#f23-画面の広さを変えられる)
- 決定の元：[利用者の決定](user-decisions.md)（2026-11-23「利用者の回答（rikai の資料〔トピック rebu…」）。文中の「上の…」は、この決定を指す。
- 一覧：[ADR の一覧](README.md)・[SPEC.md の §8](../../SPEC.md#8-利用者の判断)

（AI の判断。上の利用者の回答〔(3)：900px 以下で、右パネルの幅を、自動で狭くする〕の範囲。0.17.1。RIK-040。独立レビュー 1 回のあとで調整）**案 A＋B**：**A（900px 以下）**：右のコメントの下限を 280 → 220px・本文の最小 400px（広い窓は、これまでどおり 280・360px）・左の一覧は、狭い窓の実際の値 168px で計算する（以前は、230px で計算していた）。**B：左の一覧を、788px 未満で、自動で隠す**（168 + 220 + 400。最初は 700px 以下にしたが、701〜787px で、本文が 313px に狭まるので、直した）。保存した開閉は、書き換えない。**「☰」は、本文の上に重ねて出す**（ドロワー。本文の列は変わらない。外・Esc・「☰」・リンクで閉じる）。**狭い窓（900px 以下）での取っ手の操作は、保存した幅を書き換えない**（その窓の間だけ有効な一時の値。窓が 900px を出ると捨てる）。ask の目盛りに折り返し（前からの問題）。**パネルが 280px 未満**のときは、余白・タブ・ボタン行を詰める。**窓の大きさに応じて、既定の幅を、比例させない**：保存した幅（既定 380px）は、上限で抑えるだけ（窓を広げれば、元に戻る：F23 (3)）。**F23 の (2)(3) を、要件として変えた**（上の F23 (4)）。**振る舞い・HTTP・データの形式・安全は、変えない**。既存のテストの、意図した変更：`geometry.test.ts` の 500px の上限 280 → 220・`app.test.tsx` の 900px の `--panel-w` 310 → 332px（[検証記録](../verification.md)）
