# ADR-0044 整理フェーズ ③c：コードの土台の整理

- 日付：2026-11-24
- 種別：AI の設計の判断（もとは、SPEC.md の §8 の表の 1 行。文言は、そのまま移した）
- 決定の元：[利用者の決定](user-decisions.md)（2026-11-24「整理フェーズ ③a の、利用者の決定（整理分析の結果…」）。文中の「上の…」は、この決定を指す。
- 一覧：[ADR の一覧](README.md)・[SPEC.md の §8](../../SPEC.md#8-利用者の判断)

（AI の判断。整理フェーズ ③c。RIK-058）**見える動きを変えない、コードの土台の整理にした**：整理分析（C5・C6）の、重複の統合のうち、**振る舞いが同じと確かめられる部分だけ**を行う（幾何・画像の上限と読み込み・送る手順・キー判定）。**新しい機能も、見た目の変更も、入れない**（整理の間は、新機能を止める：利用者の決定、上の 2026-11-24 の行）。**独立レビューは、省略した**：全テストと、壊して確かめた結果で、確認する。

- **(1) `useEscape()` へのリスナーの統合は、見送った**：Esc に関わる `document`／`window` の `keydown` リスナーは、最大 5 個（`Interact.tsx`・`Overlays.tsx`〔`window`・capture・ドラッグ中〕・`Lightbox.tsx`〔拡大表示が開いている間〕・`App.tsx`〔ドロワーが開いている間〕・`appBridge.ts`〔要素選択中〕）。統合すると、**付けた順に依存する `escapeStep` の `!s.narrowSideOpen` の条件・`Overlays` の `stopImmediatePropagation` の「消費済み」の持ち回り・二重実行（`cancelAllPicks`）**に影響し、見える動きが変わりうる。リスクが、利益（リスナーの数）に見合わない。
- **(2) `<DraftField>` の統合も、見送った**（送る手順だけを `useSendGuard` にした）。
- **(3) `ratioRect` の NaN の扱いを、1 点変えた**：NaN・無限大・負の幅の入力で、NaN 入りの矩形でなく、`null` を返す。DOM の矩形では起きない入力で、NaN 入りの矩形を、あとの計算に渡すよりよいため（見える動きは、変わらない見込み）。
- **(4) 触らなかった**：`connectorPath.ts` の曲線の式・`place.ts` の配置・`layout.regionBox`（丸めとオフセットの順序が違い、統合すると、1px の差が出うる）。
- **(5) `App.tsx` のドロワーの Esc の、IME ガードの欠落は、直さなかった**：見える動きを変える（変換中の Esc で閉じなくなる）ので、この整理の範囲外。**未対応の既知の課題として、記録した**（[検証記録](../verification.md)）
