### F47 小さな UI の直し

**小さな UI の直し：最初の 5 分・小さな束**（利用者の承認：2026-11-24。整理分析の UX 分析 P8・P10。0.27.2。**F25・F35・F39・F42・F44 の、該当の部分を、これで置き換える**）：**最初の 5 分（P8）**：

- (1) **押せない Submit の理由**（F39）：`lib/turn.ts` の `submitOffReason(turn)`。コメントがない：「送るものがありません。本文の文を選んで、コメントを書くと、送れます」・AI の返信待ち：「AI の返信を待っています（送るものは、ありません）」・終了したトピック・あなたの番／未解決／すべて解決：「未送信のものがありません。…」。Submit の `title`・`#submit-wrap` の `title`・`aria-describedby` の読み上げ説明に出す（ネイティブの `disabled` は残す）。
- (2) **空の説明**：本文の短い 2 行と、畳んだ `<details>`「ほかの付け方」（範囲選択の説明）に分けた。
- (3) **「Claude Code 以外は…」の案内**：初めて「AI の返信待ち」になったときだけ、見える文字で出す（`localStorage` の `rikai-send-hint`）。以後は、コピーのボタンの `title` に、同じ案内。
- (4) **版が 1 つのページでは、「並べて比べる」を出さない**（F44 (1)。2 版になると出る）。**小さな束（P10）**：
- (5) **トースト**：画面に常にある読み上げの入れ物 `#toast-region`（`aria-live`。通常は `polite`・エラーは `#toast` 自身が `role="alert"` で、入れ物は `off`）・位置を、`bottom: 24px` から `72px` に（「範囲を選ぶ」と重ならない）・文言を `lib/messages.ts` に集めた（`RANGE_TOO_SMALL`・`RANGE_UNMEASURABLE`・`COPY_FAILED`）。**規則**：通常は「〜しました」・エラーは、理由と、次にすること・文末に「。」を付けない（`coding-guidelines.md`）。
- (6) **関連の線のボタン**（F35）：名前を「関連の線」に。状態は、`aria-pressed` と `title`（「いま：オン／オフ」「押すと、隠します／出します」）で言う。
- (7) **外観のボタン**（F36）：システムのときの名前に、「いまはダーク／ライト」を足した（例「外観：システム（自動）。いまはダーク。押すと、ライトにします」）。
- (8) **範囲選択と要素選択は、同時にオンにならない**（F25・F42）：あとから始めた側が、先の側を止める（実際の Chrome で、同時にオンにできていたため。要素選択中に右下の「範囲を選ぶ」を押す・範囲選択中にキーボードで要素選択を押す）。
- (9) **アンカーの注記**：位置の名前（`label`）を、1 行で省略し、全文は `title` に入れる（`panel/Quote.tsx`）。**保存される `anchor.label` は、変えない**（AI に届く値は、全文のまま）。**変えないもの**：サーバー・API・`.rikai/` のデータの形。**実装していない候補**：1 ページだけのトピックで、左の「ページ」の行を出さない・左のページ行の件数バッジを、右のタブ「進行中 n」と同じ数にする・ベルをオンにした直後に、トーストで知らせる・範囲のラベルの元の注意文を短くする（保存の形が変わるので、見送り）。**既知の制約**：**420px では、待ち状態の上のバーで「コピー」が切れる**（以前から。P9 の範囲）・Submit のそばに、専用の見えるヒントは、足していない（フェーズ ③ の P2 と一緒に）・Safari・Firefox での `title` の見え方は、未確認

### F48 名前と状態の言葉と上のバーの整理

### F49 拡大表示の統一と上のバーの切り替え

**画像の拡大表示の統一・上のバーの切り替え・比べる画面の復元の単純化**（利用者が、動く見本で確認して、「このまま入れてよい」と承認した：2026-11-24。整理分析の C1・C2・C3。＋利用者の依頼の挙動の統一。0.29.0。整理フェーズ ③b。**F31 (2)・F37 (3)(5)・F43・F44 (1)(5)・F48 (6) の、該当の部分を、これで置き換える**）：

- **(1) C1 添付の画像は、拡大表示で開く**：コメントの添付の画像を押すと、本文の画像と同じ拡大表示のステージ（ズームイン／ズームアウト・全体に合わせる・100%・ホイール・ドラッグ）が開く。Esc・「×」・背景で閉じる（**画像そのものを押しても、閉じなくなった**：以前は閉じた）。**ドックなし・見るだけ**（添付は、本文のブロックでなく、範囲・要素を付ける先がない。別のページ・版の画像のスレッドを出すのも不自然。返信の中の画像が、すでにステージだけで開く経路を、そのまま使った）。入口：パネルのサムネイル・パネルのカード・返信・入力欄のサムネイル（貼り付け・ドラッグ）・**拡大表示のドックの中の画像**（新規：以前は、押しても、何も起きなかった）。**ドックの中の添付を押すと、ドックの上に重ねて開く**（`ui.lightboxBack`。**1 段だけ**）：Esc で、ドックの拡大表示に戻り、もう一度 Esc で、すべて閉じる。**画面の名前と、コードの名前**：外枠は、`panel/ZoomModal.tsx`（旧 `Lightbox.tsx`）。`#lightbox` の ID と、`ui.lightbox` は、F48 の対応表のとおり、改名していない。「押すと閉じる」の枝・`openLightbox`・`zoom` の項目・`#lightbox > img`／`.close` とそのテストは、削除した。
