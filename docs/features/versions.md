### F11 資料は版で残る

> 後続の変更：F48（[名前と状態の言葉と上のバーの整理](ui-cleanup.md#f48-名前と状態の言葉と上のバーの整理)）が、この機能の該当の部分を置き換える。

**資料は版で残る**：`revisions` のたびに、新しい版（`v2`…）が `pages/<id>/vN.md` に増える。古い版は書き換えない。ビューアで版を切り替えられる（過去の版には「過去の版」と表示し、コメントは付けられない）。**v2 以降の版を見ているときは、その版の、前の版との差分を見せる**（上のバーの切り替え〔通常｜変更を重ねる｜並べて比べる〕の「変更を重ねる」で切り替える：F49。最新版でなくても出る）：ブロックを、前の版のブロックと対応づけ（同じ内容は、順序を保つ。**内容が同じでも、ブロックの種類〔段落・見出し・引用など。リストの項目は、箇条書きか番号つきかも〕が違えば、「変更」**：対応づけは保つ〔追加と削除にはしない〕。0.25.0 で変更。変更は、同じ内容のブロックの間の区間の中で、同じ種類で内容が近いもの。**比べる組が多すぎるとき（全体の予算を超える区間）は、追加と削除**）、**変更**されたブロックには左に印と、その下に折りたたみの「前の版との差分」（追加・削除された文字。半角の英数字は連続を 1 つ、日本語は 1 文字ずつの単位。**種類が変わったときは、「ブロックの種類が変わりました：p → h2」の注記**）、**追加**されたブロックには印、**なくなった**ブロックは本文の最後に折りたたみで出し、上のバーに件数（変更・追加・削除）を出す。差分の文字から選び始めても、コメントは付けられない。AI が資料を直したとき、その返信に「資料を vN に更新」と、その版へのリンクが付く。**2 つの版を、左右に並べて比べることもできる**（切り替えの「並べて比べる」：F44。同じ対応づけを使う）

### F12 コメントは版が変わっても位置が追従する

**コメントは、版が変わっても位置が追従する**：選んだ文は、`quote` と前後の文脈で、表示している版の本文から探し直す（空白の違いは許す）。ブロックへのコメントは、

- (1) 同じ内容のブロック（確実）、
- (2) 同じ種類で内容が近いブロック（推定）、
- (3) 同じ種類の、同じ位置のブロック（推定）の順で探し、**推定のときは、パネルに「近い内容のブロックに表示」「同じ位置のブロックに表示」の印を出す**。**見つからなければ**「修正で文が変わりました」と表示し、スレッドは、パネルに残す。付けた版より前の版には、そのコメントを出さない（「後の版のコメント」と表示する）

### F44 版を並べて比べる

> 後続の変更：F47（[小さな UI の直し](ui-cleanup.md#f47-小さな-ui-の直し)）・F49（[拡大表示の統一と上のバーの切り替え](ui-cleanup.md#f49-拡大表示の統一と上のバーの切り替え)）の (1)(5)が、この機能の該当の部分を置き換える。

**版を並べて比べる**（利用者の用途：2026-11-23。`html-app-review`＝画面の比較・位置・ボタンのデザインのレビュー。「前の版と並べて比べる」を、`html-app` の段階 3 の先頭の候補に挙げていた。「一旦全ての依頼の実装を全て進めてほしい。明日朝あたりレビューする」〔2026-11-23〕→ 細部の設計は AI の判断：§8）：

- (1) **入口**：上のバー（`DocBar`）の、版の選択の近くの切り替え〔通常｜変更を重ねる｜並べて比べる〕の「並べて比べる」（F49）。選んでいるときに、もう一度押すと、閉じる（通常に戻る）。**比べる画面の中にも、同じ切り替えが出て、「通常」「変更を重ねる」で、1 クリックで戻れる**。Esc・「閉じる」でも閉じる。**版が 1 つのページでは、切り替え自体を出さない**（2 つ以上になると出る。押せないボタンを、見せない：F47）。
- (2) **画面**：本文の領域に、**左右の行**で出す。上に、説明（「読み取り専用」・「左から右への変更を強調」）・**左右の版のプルダウン**（各欄に 1 つ。**同じ版を左右に選んでもよい**〔差分なし。「同じ版を、左右に選んでいます」と出す〕・**左を新しい版にする向きも許す**〔強調は、常に「左から右への変更」〕）と、札（最新／過去の版：色だけにしない）・変更の件数（変更・追加・削除・同じ）・**「変更のある所だけ見る」**（続く、変わらないブロックを、件数つきの折りたたみにする）・「閉じる（Esc）」。
- (3) **行**：**ブロックごとの行**に、F11 の対応づけ（`matchBlocks`）で、左右のブロックを並べる（`lib/compare.ts` の純粋関数 `alignRows`）。**行は、右の本文の順**。**削除は、前の版でそのブロックの次にあったブロックの直前**に出す（同じ場所に、削除と追加があるときは、「削除 → 追加」の順）。**左右が同じ行に入るので、スクロールの同期は要らない**（1 つの縦のスクロール）。**札**：「追加」（右）・「削除」（左）・「変更前」（左）・「変更後」（右）：**色だけに頼らない**。**内容が同じでも、ブロックの種類が違えば「変更」**（段落 → 見出しなど：F11）。**変更の行は、右の欄の下に、文字の差分**（折りたたみ。**開いたときに計算する**。種類が変わったときは、「ブロックの種類が変わりました：p → h2」の注記）。**変更が多くて、近さによる対応づけを、一部の区間でしていないとき**（F11 の予算を超えた：`limited`）は、上に、「変更が多すぎて、対応づけていません（追加と削除として並べています）」と出す。**左右の本文は、通常の表示と同じ描き方**（無害化・Mermaid・コード・表・`html-app`）。
- (4) **既定の組**：**右＝いま見ている版・左＝その 1 つ前**（最新版を見ていれば、左 v2・右 v3。過去の版 v2 を見ていれば、左 v1・右 v2。v1 を見ていれば、左 v1・右 v2）。
- (5) **読み取り専用**：コメントの追加・範囲選択・要素選択・拡大表示は、出さない（上に、「コメントは、最新版の本文で付けます」と書く）。**比べている間は、右のコメント欄を隠し、通常の本文は外す**（既存の下書きは残る）。**開くとき**：見ていた版の印（`View.key`）と、本文のスクロール位置を、`compare.from` に控えるだけ（**入力欄・選んでいるスレッドは、保存も消しもしない**：入力欄の状態は、そのまま残り、DOM は、隠れて存在する。書きかけの文・添付の画像も、残る）。**閉じるとき**：見ている版が同じ（`View.key` が同じ）なら、スクロール位置を戻す（`Article` が、描き終わったあとに、1 度だけ受け取る。2 フレーム後にも置き直すが、その間に利用者が動かしていれば、置き直さない）。入力欄は、残っているので、同じ対象・同じ文・同じ画像で、続けられる。**比べている間に、版が変わったとき**（新しい版が届く・過去の版へ戻る）**は、比べていないときと、同じ 1 つの経路**（`moveComposer`。0.27.1）：**最新版へ**：入力欄と文を残し、確かめの印（`verify`）を付け、本文を描き終えたあと、`Article` が、既存の `markPending`（`findQuote`・`locateBlock` の探し直し）で、対象が新しい版の本文に見つかるか確かめる：**見つかれば、同じ対象・同じ文・同じ画像で、続ける**／**見つからなければ、入力欄を閉じ、書きかけを「対象を失った下書き」へ移す**。**最新版でない版へ**（コメントは最新版にだけ付けられる）：すぐ、「過去の版にあります」の理由で、「対象を失った下書き」へ移す。**ページ・トピックを移ったとき**：比べる画面は閉じ、書きかけは、「対象を失った下書き」へ移す（理由「別のページにあります」「別のトピックにあります」）。**「対象を失った下書き」**（`ui.lostDraft`・`panel/LostDraft.tsx`）：移すときに、`drafts.composer`・`drafts.imgs.composer` を空にするので、**次に開く入力欄には、何も入らない**（別の対象に付かない）。トーストで知らせ、パネルの上に、注記つきで 1 件だけ出す（続けて失ったときは、文をつなぐ）。文は、文字のまま出す（React の子）・「コピー」（クリップボードの権限は、押したときだけ。失敗したら、「文を選んでコピーしてください」）・「破棄」。画像は、コピーできないので、枚数だけ出す。**メモリだけ**（`localStorage` は使わない）。
- (6) **`html-app` の枠**：左右とも、本文と同じ経路（`fillApps` の `compare` のオプション）で、**同じ隔離**（`sandbox="allow-scripts"`・`APP_CSP`・橋・登録簿）。枠ごとのツールバー・「この枠にコメント」・要素選択・拡大表示は、出さない。**比較用のツールバー**（画面の上に 1 つ）が、**左右のすべての枠に、同じ幅**（375・768・1280・1920・自動。F40 の縮小表示も）**・外観**（枠だけのライト／ダーク）**を、まとめて適用する**。**枠の中の状態は、共有しない**（左右の枠は、独立：片方でスライダーを動かしても、もう一方は変わらない。上に、一文で書く）。左右の幅・外観の覚えは、本文の枠の覚えと混ぜない（本文の枠の設定を、上書きしない）。描き直し・版の切り替え・閉じるときは、枠を、橋から外す（`releaseApps`）。
- (7) **状態**：**`ui.compare`**（左右の版・幅・外観・変更のある所だけ・開く前の画面〔`from`：見ていた版の印と、スクロール位置〕）が、**唯一の所有者**。**URL のハッシュには持たない**（再読み込みで閉じる）。**ページ・トピックを移ると閉じる。同じページの中の、版の切り替えでは閉じない**。
- (8) **版の取得**：通常の表示と同じ `usePage`。**片方が取れなくても、その欄にだけ、エラーと「再読み込み」を出し、もう一方は出す**。**新しい版が届いても、枠は作り直さず、「右を vN にする」の案内だけ出す**。
- (9) **Esc**：枠の外は、`escapeStep` の 1 項目（閉じる）。**枠の中にフォーカスがあるときは、橋の `esc` の知らせ**（F43 (8)）**を、比べる画面の枠にも渡して、閉じる**。**結果：枠のコードが、偽の `esc` を送ると、比べる画面が閉じる**（データには触れない：拡大表示と同じ。許容）。
- (10) **狭い窓**（760px 未満、または、欄が 520px 未満）：行の左右を、**上下に並べる**（空白の欄は隠し、「左 v2」「右 v3」の札で、どちらの版か分かるようにする）。
- (11) **変えないもの**：サーバー・API・`.rikai/` のデータの形（`usePage` だけを使う）。**対象外**：資料の中に、2 つの枠を横に並べる書き方・返信（カード）の中の枠（**不要と決まった**：利用者の決定：2026-11-24。§7）。**既知の制約**：**F11 の上限（`MAX_PAIRS`）を超える、全面の書き換えは、「変更」ではなく「追加＋削除」として並ぶ**（実測：4000 段落が全部違うと、追加 4000・削除 4000。上の案内が出る。描画は軽い：許容）・入れ替わった「変更」の行があると、左の欄の順が、前の版と少しずれる・引用の入れ子（`>` → `> >`）とコードブロックの言語（`js` → `ts`）は、種類の変化として数えない（誤検出ではなく、取りこぼしの側）・実際のマウス・ほかのブラウザは、未確認

### F50 Markdown を保存

**Markdown を保存**（利用者の依頼：2026-11-24。「対象の Markdown をダウンロードできるようにしたい」→「進めてください」。0.30.0。RIK-062）：

- **(1) 何を保存するか**：**いま見ているページの、いま見ている版の、元の Markdown**（最新版でも、過去の版でも、子ページでもよい）。**コメントは含めない**。**画像は、`assets/…` の参照のまま**（zip は作らない：画像のファイルは含まれない）。**`html-app` の枠は、本文のコードブロックのまま**。**「変更を重ねる」を見ていても、保存するのは元の Markdown**（差分の装飾を入れない）。
- **(2) 保存の仕方**：**ブラウザの中で保存する**（`Blob` と `<a download>`。`web/lib/download.ts`）。**サーバーは増やさない・新しい通信は起きない**：App が、本文の描画のために、すでに取っている本文（`usePage`）を、そのまま使う。内容は、文字列を UTF-8 にしただけ（BOM・CRLF・末尾の改行を変えない）。`<a download>` を `document.body` に足して `click()` し、直後に消して、`revokeObjectURL` する（失敗しても `finally`）。`innerHTML` は使わない。
- **(3) ファイル名**：**`<トピック>-<ページ>-v<版>.md`**（root ページは、ページ名なしの `<トピック>-v<版>.md`）。英数字以外は、連続を 1 つの `-` にして、前後の `-` を落とす（何も残らなければ、`topic`・`page`）。トピック名・ページ ID は、`checkSlug`（`SLUG_RE`）で検査済みで、**英小文字・数字・ハイフンだけ**なので、消毒は多重防御（単体テストで固定）。
- **(4) 置き場所と名前**：**上のバー `#top` の、ベルの左**（`layout/SaveMarkdown.tsx`）。名前は**「Markdown を保存」**（アイコンつき）。**`#docbar` には置かない**：幅が足りない（1360px・右のコメント 380 で「過去の版」を見ていると、`#docbar` は、幅 750px のうち約 690px を使っていて、ボタンを足すと 2 行に折り返し、「1 行」〔F48〕を壊す。ラベルつき 140px でも、「保存」だけの 66px でも入らない）。**560px 以下は、ラベルを隠して、アイコンだけ**（名前は `aria-label`・`title`。既存の `.turn-t` と同じ扱い）。420px では、さらに `#top` の余白を詰めた（詰めないと、状態の札が「AI に送る」に重なった）。
- **(5) 出さない・押せない条件**：**並べて比べる画面では、出さない**（左右のどちらか、決まらない）。**本文が未取得、または取得に失敗しているあいだは `disabled`**（理由は `title`：前の版を、新しい版の名前で保存しない）。**空の本文は、0 バイトのファイルとして、保存できる**。
- **(6) 通知**：**Blob を作れなかったときは、エラーのトースト**（`SAVE_FAILED`）。**成功のトーストは出さない**（ブラウザ側の保存の結果は、見えないため）。**変えないもの**：サーバー・API・`.rikai/` のデータの形。**対象外・残る課題**：**画像つきの zip・コメントつきの書き出しは、作っていない**（別の機能）・560px 以下はアイコンだけ。**確認していない範囲**：本物のマウス・他のブラウザ・他の OS
