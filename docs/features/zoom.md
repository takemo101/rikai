### F37 本文の画像と図を拡大表示できる

> 後続の変更：F48（[名前と状態の言葉と上のバーの整理](ui-cleanup.md#f48-名前と状態の言葉と上のバーの整理)）・F49（[拡大表示の統一と上のバーの切り替え](ui-cleanup.md#f49-拡大表示の統一と上のバーの切り替え)）の (3)(5)が、この機能の該当の部分を置き換える。

**本文の画像と図を、押して、拡大表示できる**（利用者の依頼：2026-11-23。「本文の画像要素を、クリックしたら拡大表示されるようにしたい。図も同じく拡大表示が欲しい」。背景：拡大表示は、コメントに添付した画像だけだった〔F31 (2)〕。本文の画像・図は、拡大できなかった。**AI が、比較ページで「画像を押すと大きく出ます」と、誤って案内した**。**0.24.0 で、個別表示（F43）に拡張した**：対象に `html-app` の枠を加え、開いたままコメントを入力でき、範囲・要素を選べる。この行は、F43 の土台〔拡大・ズーム〕）：

- (1) **対象**：本文（`#article`）と、AI の返信の本体（`.msg .body.md`）の、`img`（`assets/` の画像）・Mermaid の図・**draw.io の図〔F52。Mermaid の図と同じ経路〕**・インラインの `<svg>`。**対象外**：外部画像のブロック表示（`.img-blocked`）・リンクの中の画像・ボタンの中の svg（`html-app` の枠は、F43 の「個別表示」から）。
- (2) 押すと、**拡大表示**（外枠は `#lightbox`）で、大きく出る。**図は、押された SVG を `cloneNode(true)` で複製し、`id` に接頭辞 `zoom-` を付ける**（`url(#…)`・`href="#…"`・`aria-labelledby`・`<style>` の `#id` 選択子も書き換える：`lib/zoomSvg.ts`。同じ `id` が 2 つあると、`url(#…)` が元を指すので、複製の `id` は、重ならない形にする）。**HTML を文字列から作らない・`innerHTML` を使わない**。**本文の DOM には、何も足さない・動かさない**（`#article` の中身は、開いても閉じても、同じ：番号・線・位置づけが崩れない）。
- (3) **ズーム・移動**：全体表示〜**800%**（等倍が 100%）・「ズームイン」「ズームアウト」「全体に合わせる」のボタン（`aria-label`・`title`）・ホイール（カーソルを中心に）・ドラッグで移動・ダブルクリックで、全体表示 ↔ 等倍・キー `+`・`-`・`0`・Esc／背景／「×」で閉じる（ドラッグの終わりでは、閉じない）。ラスタ画像は、全体表示で最大 2 倍・SVG は、窓いっぱいまで。図の地は、画面の紙の色（ダークでは、暗い地。1px の縁）・画像の地は白。`role="dialog"`・`aria-modal`・`aria-label`・開いたら、フォーカスを移し、閉じたら、元の要素へ戻す（F43）・Tab は、ボタンだけを回る。**添付の画像（F31）も、同じ拡大表示で開く**（見るだけ：F49）。
- (4) **開かない操作**：文字を選ぶ操作・押した位置から 4px を超えたドラッグ・選択範囲がある状態・範囲を選んでいる最中・修飾キーつき・右ボタン。
- (5) **コメントの付いた画像・図も、押すと、拡大表示が開く**（利用者の依頼：2026-11-24：F49。コメントは、右のパネルのカード・拡大表示のドックから開く）。**入口のバー**（`#actbar`。ブロックにマウスを置いたとき〔`mode: 'blk'`〕）に、**「拡大表示」ボタン**（`#act-zoom`。「コメント」の左。画像・図を含むブロックのときだけ。コメントの有無に関係なく、拡大表示を開く。入力欄は、開かない）。文を選んだバー・コード・表・外部画像・`html-app` には、出さない（`html-app` の入口は、見出しの「拡大表示」：F43・F48）。**対象外**：回転・複数の画像のギャラリー・画像の保存・ピンチ（タッチ）。**既知の制約**：開いている間に外観を切り替えても、複製した図は、元の色のまま（開き直すと直る）・図の複製は、押した時点の見た目で固定（図の中の動き・hover は効かない）・800% を超える拡大はできない・1 つのブロックに複数の画像があるとき、バーの「拡大表示」は、最初の 1 つだけ・バーが出ている間に窓の大きさを変えると、位置が古いまま（前からの挙動）

### F43 個別表示でコメントする

> 後続の変更：F48（[名前と状態の言葉と上のバーの整理](ui-cleanup.md#f48-名前と状態の言葉と上のバーの整理)）・F49（[拡大表示の統一と上のバーの切り替え](ui-cleanup.md#f49-拡大表示の統一と上のバーの切り替え)）が、この機能の該当の部分を置き換える。

**個別表示（フォーカスビュー）：画像・図・`html-app` の枠を、本文から離して、開いたまま、範囲や要素を選んでコメントできる**（利用者の依頼：2026-11-23。「拡大表示を開いたままでコメント入力したい。画像や図形や HTML も、本文に直接ではなく、拡大モードのように個別で表示するモード上で開いて、そこに範囲選択や要素選択でコメントを入れられるようにしたい。特に画像や図形は、細かいところを範囲選択してコメントを残したい」。F37 の拡大表示を「個別表示」に拡張した。画面の名前は、いまは「拡大表示」：F48）：

- (1) **対象**：本文・AI の返信の `img`・Mermaid の図・draw.io の図（F52）・インラインの `<svg>`（F37）に、**`html-app` の枠**を加える。**ブロックそのものが `<img>` の画像**（資料の生の `<img width height>`）も開ける（`imgSrcOf` が、自分自身が `HTMLImageElement` なら、その `src` を使う。ラベルも「画像: alt」）。
- (2) **入口**：F37 の「拡大表示」ボタン（入口のバー）・画像／Mermaid のブロック／`svg` に `tabindex="0"`・`role="button"`（**Enter・Space**）・**本文の画像・図を押す**（コメントの有無に関わらず、この拡大表示が開き、ドックに、そのブロックの全コメントが出る：F49）・`html-app` は、見出し（`AppToolbar`）の「拡大表示」ボタン。**閉じたとき、開いた要素にフォーカスが戻る**（要素が消えていれば、本文のその入口）。
- (3) **画面**：窓いっぱいのオーバーレイ（`role="dialog"`・`aria-modal`・`#app` の、ほかの要素を `inert`・`Tab` は窓の中だけ）：**左＝ステージ**（画像・図：拡大・移動・ホイール・「全体に合わせる」・「100%」。`html-app`：**新しい iframe を作る**〔本文の枠を移さない：移すと、再読み込みで状態が消え、本文の枠が壊れるため。同じ隔離＝`sandbox="allow-scripts"`・同じ `APP_CSP`・同じ src。`apps.ts` から `appFrameDom` を抜き出して共有〕。幅の切り替え・縮小表示・枠だけのライト／ダーク。**枠の幅の設定（自動・375・768・1280・1920）の既定は、本文の枠が、いま選んでいる設定**：揃うのは**設定で、px ではない**〔(10)〕）・**右＝コメントのドック**（窓が 760px 未満では、下のシート）：新しいコメントの入力欄（既存の `Composer`。**`composer` の状態を共有する**：拡大表示で書いた下書きは、閉じたあとも、パネルに残り、パネルの「AI に送る」で送る）と、**このブロックの既存コメントのカード**。**枠から取った情報〔F45〕は、ドックでも、「情報の行」として出る**（入力欄の上：下書き〔「外す」あり〕。既存のカード：「外す」なし）。
- (4) **ステージの道具**：**「範囲を選ぶ」**（ドラッグ。画像・図は、拡大した状態の座標から、F25 の `cropMedia` で、**元の解像度から**切り出す〔ズームの倍率を、座標に反映。図は、自然な大きさを渡す〕。**錨は、F25 と同じ形**〔ブロックに対する割合の `region`。**縦横比を変えた画像〔本文 634×600 に引き伸ばしなど〕でも、画像の内容に対する割合なので、ずれない：実測**〕。`html-app` は、F42 の枠の画像）・**「要素を選ぶ」**（`html-app` のみ。F42 の `pick-start`。入力欄は、空で開き、要素の情報は、ドックの入力欄の上の情報の行に出る〔F45〕）・**状態の添付は自動**（拡大表示の枠の `rikai.state`。`frameMeta.state`）。**既存の範囲コメントの枠と番号**を、ステージに重ねる（ズーム・移動・縮小に追従。押すと、ドックのそのスレッドが選ばれる）。
- (5) **Esc の順序**（`lib/escape.ts` の 1 か所）：範囲選択 → ドラッグ中 → 道具（範囲選択・要素選択）の中止 → 閉じる（**書きかけの下書きは消えない**）。**日本語の変換中〔IME〕の Esc は、処理しない**（`isComposing` か `keyCode 229` のとき：`escapeStep`・`Interact`・`ZoomModal`・`onPickKey`・`Overlays` の Esc・橋の `esc` 転送。`Composer`・`ThreadCard` の Ctrl／⌘＋Enter も同じ）。
- (6) **開いたまま、本文が更新されたとき**：ブロックが同じなら、開いたまま・既存のコメントの重ねを更新・ブロックが変わった／消えたら、閉じる。
- (7) **データの形は変えない**（`.rikai/`・API・`apply`／`poll` の入力・SKILL.md の入力の形。**0.26.0 で、コメントのメッセージに、省略できる `frameMeta` が増えた：F45**）。**拡大表示の枠の錨は、本文の元のブロック**。
- (8) **拡大表示の枠からの `pick`・`state`・`snapshot`・`esc` は、本文の枠と同じ検査**を通す（`registerFrame` で、橋の登録簿に入れ、閉じるとき `releaseApps` で外す）。**枠の中の Esc**：枠の中にフォーカスがあると、Esc は枠が受けて、親に届かない → 橋が、（選択モードでないときの）Esc を `{type:'esc'}` で、親へ送る（150ms に 1 回まで・押しっぱなしの繰り返しと Esc 以外は、送らない）。親は、`parseEsc`（`shared/htmlapp-bridge.ts`。この 2 キーだけ）・`e.source`（登録簿）・頻度（1 つの枠につき 1 秒に 6 回）を検査し、**拡大表示の枠だけ**（`FocusApp` が `registerFrame` の `handlers.onEsc` を渡す。0.25.0 から、版を並べて比べる画面〔F44〕の枠も）が、`escapeStep()` に流す。選択モードの Esc は、既存の `pick-cancel` だけ（二重にならない）。
- (9) **`html-app` の範囲の基準の修正（F25 の不具合）**：`html-app` のブロックの `frameOf`（範囲の基準）が、見出しのツールバーの最初のアイコン（15px の `svg`）になっていた → **枠の置き場（`.appview`）にした**（本文の範囲選択・範囲の重ね・関連の線・拡大表示の写しを、同時に）。
- (10) **`html-app` の範囲の、枠の幅のずれを知らせる**：揃えるのは、枠の幅の**設定**（自動・375・768・1280・1920）で、**px ではない**。**「自動」のとき、本文の枠は本文の幅（例 634px）・拡大表示の枠はステージの幅（例 980px）で、px は違い、レイアウト（`@media`）が違いうる**（例：本文の枠で 1 列・拡大表示の枠で 2 列：拡大表示で選んだ範囲が、本文の枠では別の要素を指す）。**px が違うときは、知らせる**：**範囲の錨のラベルに、選んだときの枠の幅を書き**（`範囲：…（枠の幅 980px で選択）`・長さ 120 以内）、**ステージの道具の帯に、琥珀色で「本文の枠と幅が違います（本文 634px）」と出す**（同じ範囲が、別の要素を指すことは、防げない：知らせるだけ）。
- (11) **古い基準の範囲のクランプ**：古い基準の `html-app` の範囲が、大きくはみ出して、本文の高さを伸ばす（`{x:0.5,y:2,w:40,h:8}` で、本文の枠が 357×1472px・拡大表示の枠が 39200×960px になった）→ **描画だけ**、`clampRegionRect`（`overlay/layout.ts`）で、`html-app` のブロックの範囲の枠の比率を、基準の箱の周り `[-1, 2]` に収める（空なら描かない。本文と拡大表示の両方。**保存データは書き換えない**・画像・図・文の範囲には使わない）。
- (12) **コメントのドックの中の添付画像は、押すと、ドックの上に重ねて拡大表示で開く**（見るだけ。1 段だけ。Esc でドックに戻り、もう一度 Esc ですべて閉じる：F49）。
- (13) **対象外**：回転・ギャラリー・画像の保存・ピンチ（タッチ）・返信の中の枠。**既知の制約**：**0.24.0 より前に保存された、`html-app` の範囲コメントは、位置がずれる**（`x` が 1 以上：枠が出ない〔番号の丸は出る〕／`x` が小さく、`y`・`h` が大きい：高さ約 6000px の枠が、遠くに出る：(11) で、描画は収める）。`.rikai/` は書き換えない・古い基準を、確実に見分ける方法がない・影響は、0.22.1〜0.23.0 の、作者の試用分だけ（推測）なので、**許容**する・本文の枠の状態（スライダーなど）は、拡大表示に引き継がない（新しく読み込む）・枠の中の Esc は、拡大表示の枠だけが、親へ転送する・枠の中の `Tab` は、拡大表示の窓から出るのを、`inert` と、フォーカストラップで止める・範囲を選べるのは、ブロックの最初の画像・図だけ（2 つ目以降は無効。ブロック全体へのコメントは、出せる）・ドックの上に重ねた添付から戻ると、ドックの画面が作り直されるので、ズームの位置・ドックの中の `html-app` の状態は戻る（下書きは消えない）・ステージ上の、入力中の範囲の枠（点線）は、F31 のようにドラッグで調整できない・拡大表示の枠の iframe は、開いた時点の版のまま（ブロックが変われば、閉じる）・**実際のマウス・タッチ・ほかのブラウザ・本物の IME は、未確認**（IME の変換中の Esc は、合成イベントで確認しただけ）
- (14) **後続の変更**（F56。0.1.6・0.1.7）：**表示中の `.fv-box` は、枠の中の操作を塞ぐ**ので、**「コメントの印を隠す」ボタン**（ドックの見出し。`ui.marks`）で、拡大表示の枠・番号の丸・関連の線をすべて隠せる（隠すと、ドックのカードはそのまま）。入力中の枠は、押せない破線で残る。
- (15) **html-app の番号の丸は、画像・図と同じ規則**（F56。0.1.7）：html-app の丸は、`.fv-box` の中でなく、ステージ（`.fv-appstage`）の中の `.fv-chip` として置く。左上の外側（左 −0.5px・上 −20.5px）・上に余地（24px）がないときだけ、内側の 3.5px・3.5px（画像・図・html-app の 4 種類で同じ）。それまでは、html-app の丸だけが、常に枠の内側に入っていた。

### F55 拡大表示でも関連の線で結ぶ

**拡大表示で、ステージ上の範囲の枠と、右のドックのコメントのカードを、本文と同じ「関連の線」で結ぶ**（利用者の依頼：2026-11-25。「本文ではコメントと対象の範囲・文が線でつながっている。画像・html-app・図形を拡大したとき、横にコメントが出るが、繋がりが番号しかない。同じように線でつなげて表現することは可能ですか」→ 方針を示して「はい、お願いします。進めてください」→ 動く見本で「全体的にいい感じなので、レビューして問題なければこれで進めて欲しい」）。0.1.5。設計の判断は [ADR-0059](../decisions/0059-focus-links.md)。F35（本文の線）・F43（個別表示のコメント）の続き。

- (1) **対象**：画像・Mermaid／draw.io／インライン SVG の図・`html-app`。実装は `focus/FocusLinks.tsx`。
- (2) **端点**：ステージ側は、`.fv-box` の右端の縦の中央の外 4px（入力中は外 10px）。ドック側は、番号の丸の高さの、カードの左端。**範囲を持たないコメント**（「この対象全体」）は、枠がないので、対象（`.lb-stage`。`html-app` は `iframe`）の右端の外 6px から引く（本文のブロックと同じ規則）。文など、引く先のないコメントは、引かない。同じ高さの枠が複数あるとき、始点は、カードの順に少しずつずれる。
- (3) **追従**：ズーム（キー・ホイール・ボタン）・ドラッグ移動・ドックのスクロール・窓の大きさ・カードの開閉・枠の増減・`html-app` の幅の切り替えに、線が追従する（`requestAnimationFrame` に 1 回へまとめて測る。**ドックにタブはない**）。
- (4) **状態と見た目**：カードを選ぶと active・枠にマウスを置くとドックのカードと線が光る（linked。今までなかった動作の追加。**枠にマウスを置いたまま Esc で閉じても、光りは残らない**：`FocusLinks` が外れるとき、自分が付けた光りだけを戻す）・入力中は点線の pending。色・点線・resolved・edge は、本文（F35）と共通（`connectors.css` を `:is(#links, .fv-links)` に広げた）。ダークは `--accent` と一致。終了したトピック（F54）でも引く。
- (5) **オン・オフ**：本文の「関連の線」（F35）と**同じ `ui.links` を共有**する。ドックの見出しに、同じボタン（`panel/LinksToggle.tsx`。右パネルのボタンも、これを使う）。拡大表示で切ると、閉じてもオフのまま・本文の線も同じ状態。
- (6) **重なりと安全**：`#lightbox > .fv-links` は `z-index: 4`（道具は 5）・押せない（`pointer-events: none`・`aria-hidden`）。線はカードの左端で止まり、カードの文字に掛からない。**線の上からのドラッグでも、移動も範囲選択もできる**。**`iframe` の中へは入れない**（`sandbox`・CSP・橋は不変：F28・F42・F45）。**拡大表示を開いている間は、後ろの本文の `#links` を隠す**（線がまぎれるため）。
- (7) **窓が 760px 未満**（ドックが下のシート）のときは、線を引かない（右へ引き出して左のカードへ戻る線は、本文の `connectorPath` の形では描けないため。番号で結ぶ）。1100・900px では引ける。
- (8) **範囲の基準（確認した規則）**：範囲コメントの比率は、**作るときも、表示するときも、描かれた図の `svg`**（本文は `frameOf`・拡大表示はステージの複製）に対するもの。**図・画像のコメントを API で直接作るときは、ノードの比率を DOM から取り、`blockId`・`blockHash` も DOM の `data-bid`・`data-bhash` から取る**（丸い数や、決め打ちの番号を使わない：見本の `threads.json` の番号が 1 つずれて、枠が見出しの箱に描かれた例がある。[ADR-0059](../decisions/0059-focus-links.md)）。
- (9) **既知の点**：範囲コメント（`rect` つき）が、画像・図・`html-app` でないブロックを指していても、いまは、見出しなどの箱に枠を描く（描かない・API で拒否するかは、別の仕様の判断：変えていない）・拡大表示で、ほかの枠の上を通る水平の引き出し線が、その枠の上に重なって描かれる（本文の線が文字の上を通るのと同じ見た目）。F43 の「番号だけで結ぶ」ことは、窓が 760px 未満の場合だけになった。
- (10) **後続の変更**（F56。0.1.6・0.1.7）：ドックの見出しに、「コメントの印を隠す」ボタンが並ぶ（`.fv-marks-toggle`。`ui.marks` を、本文・右パネルと共有）。隠している間は、枠・番号の丸・関連の線は、引かれない（出すと戻る。入力中の線は残る）。
