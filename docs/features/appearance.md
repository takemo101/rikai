### F22 コメントと本文の位置が分かる

**コメントと本文の位置が分かる**：

- (1) 本文の順に、コメントに**番号**をつけ、本文の対象（選んだ文・ブロック・画像や図の範囲）と、右のカードの両方に出す（本文の中で見つからないスレッド・後の版のコメントには、付けない）。**番号の印は、文・ブロック・範囲の、すべて、同じ見た目（丸）・同じ位置**（要素の外の層〔絶対位置〕に、記事の左の余白へ、対象の上端〔文は、最初の行の高さ。範囲は、範囲の上端の高さ〕にそろえて出す。利用者の指摘：2026-11-22。要素の中だと、表・コード・図の箱の `overflow` で切れる・横スクロールで流れる）。同じ行（高さの差 4px 未満）の印は、横に並べ、折り返して背が高くなっても、下の印に重ならない（同じ行に多数あるときの並べ方は、F35 の「同じ行の、複数のコメント」）。色：青＝未解決・灰色＝解決済み・オレンジ＝入力中（「新」）。**本文の要素・文字を足さない**（コメントの位置づけに使う本文の文字が、変わらないように）。範囲の枠は、枠だけを描く（番号は、左の余白の丸）。
- (2) 右のカードにマウスを置くと本文の対象が、本文の印に置くとカードが、光る（本文の印に置いたとき、カードが見えない所にあれば、見える所まで動かす）。
- (3) 入力欄を開いている間、対象を、本文で**オレンジ**に強調し、入力欄は、対象の位置の順に、スレッドの間へ入れる（いつも一番上、にしない。対象が見つからないときは、先頭）。
- (4) 入力欄を閉じる（「やめる」・「コメントを追加」）と、強調を外す。**カードを対象の横に並べる案（Google ドキュメント型）は、これを使ってもらってから、要否を決める**（§7）

### F23 画面の広さを変えられる

**画面の広さを変えられる**：

- (1) 左の一覧（トピック・ページ）を、上のバーの「☰」で、しまう／出す（しまうと、本文の幅の上限を 760px から 920px に広げる）。
- (2) 右のコメントの幅を、左の境目の取っ手のドラッグ（左ボタンだけ）・左右の矢印キーで変える（**1101px 以上の窓は、280px〜画面の 70%**。ただし、左の一覧が開いているときは、それも引いて、本文の領域が 360px 以上、残る幅まで）。ダブルクリックで、もとの幅（380px）。（コメントの見出しにあった「広くする／狭くする」のボタンは、F27 でなくした：2026-11-22）

- (4) **狭い窓の規則**（**要件の変更：2026-11-23**。利用者の依頼：「900px 以下で、右パネルの幅を自動で狭くして、本文の列を広げる」。独立レビューの指摘で調整。**0.28.0 で、自動で隠す境界を 1100px に上げた**：利用者の決定、2026-11-24。半画面〔720〜1100px〕を使う前提）：**900px 以下**（CSS の `@media (max-width: 900px)` と同じ境界）は、右のコメントの下限を **220px** に（上限は、窓の 70% と「窓 − 左の一覧〔168px〕 − 本文の最小」の小さい方。下限 220 は、下回らない）・**本文の最小は 400px**。保存した幅は、上限で抑えるだけで、書き換えない（窓を広げれば、元の幅に戻る）。**狭い窓（900px 以下）での取っ手の操作は、保存した幅（`panelW`）を書き換えない**：その窓の間だけ有効な一時の値にする（保存しない。窓が 900px を出ると捨てる。再読み込みで元に戻る）。広い窓では、従来どおり、保存する。**1100px 以下**（0.28.0。以前は、788px 未満）は、左の一覧を、**自動で隠す**（保存した開閉は、書き換えない）。「☰」は、見えている状態を `aria-expanded` で示し、押すと、**左の一覧が、本文の上に重ねて出る**（ドロワー。幅 230px。**本文の列は変わらない**。外を押す・Esc・「☰」・一覧の中のリンクで閉じる。保存しない）。重ねて出した一覧は、自動で隠す窓を出たときも、自動でしまう。**1101px 以上は、保存した開閉のまま**（本文の列の横に並ぶ）。**1100px 以下で、保存した右の幅が、既定（380px）のままなら、280px を使う**（取っ手で変えた幅は、そのまま。保存した値は、書き換えない）。取っ手の最小値・ドラッグ・矢印キーは、窓の下限と上限に合う。**右のパネルが 280px 以下**のときは、余白を詰め（14 → 10px）・タブは、名前の下に件数を縦に積み（名前は変えない）・カードと ask の内側の余白・ボタン行の間隔を詰め・返信の入力欄に最小の高さ（96px）を置く。ask の目盛り（`scale`）は、折り返し（7 段以上・220px でも、パネルからはみ出さない）。**本文の幅（実測。担当の報告）**：1360px：750 → 750／1100px：490 → **820**（左は隠れる・右 280）／900px：400 → **620**。**420px は、対象外**（本文は 200px。以前から：F48）

### F33 落ち着いた見た目と過去のコメントの整理

> 後続の変更：F48（[名前と状態の言葉と上のバーの整理](ui-cleanup.md#f48-名前と状態の言葉と上のバーの整理)）が、この機能の該当の部分を置き換える。

**落ち着いた見た目にする。過去のコメントを、見やすくする。変更ブロックの印を、細くする**（利用者の依頼：2026-11-22。「スタイリッシュで、落ち着いた感じに」「過去のコメントも、もっと表示しやすく」。選ばれた方法：解決済みの一覧・切り替え・番号でそのカードだけ。「古いやり取りの 1 行の要約」は、選ばれなかった。「左からグラデーションの UI は、何」という質問への対応）：

- (1) **見た目**：色数を絞り（温かい無彩色の土台・落ち着いた青灰色の差し色・黄色／オレンジ／赤／紫は、状態の印だけ、弱く）・線を薄く・角を丸く（カード 10px・本文 12px）・影を弱く・文字は、やわらかい濃さ（`--ink: #2b2e33`）・行間 1.7・見出しを軽く。
- (2) **右のパネルの切り替え**：上に、「進行中」「解決済み」「すべて」（それぞれの数つき。既定は「進行中」）。**この見出し・切り替え（と、(3) の帯）は、スクロールしても、パネルの上に固定する**（利用者の指摘：2026-11-22）。**解決済みは、1 行**（番号・対象のはじめ・最後の発言のはじめ。押すと、そのカードが開き、「一覧の 1 行に戻す」で戻る）。本文の、解決済みの**文の強調**を押すと、一覧の中で、そのカードが開く（番号を押したときは、(3)）。
- (3) **本文の番号を押すと、そのカードだけを、大きく見られる**（古いやり取りも、たたまない。上に「すべてのコメントに戻る」（矢印のアイコンつき）と「N 番のコメントだけを表示中」。入力欄が開いていれば、その下）。別のページ・版へ移ると、戻る。
- (4) **前の版から変えたブロックの印**：**右端**の細い緑の線だけ（左は、コメントの番号が出るので、右端：利用者の指摘：2026-11-22。背景のグラデーションは、やめた：重く、何の印か分かりにくい、という指摘）。**凡例**（「右端の緑の線：前の版から変えたところ」）を、上のバーに出す（変更・追加があるとき）。（2026-11-23 に、デザインを作り直した。現在の見た目は、`app/src/web/styles/app.css`。(1) の色・形・文字の値は、これより古い）

### F35 コメントと本文の対象を線で結ぶ

> 後続の変更：F47（[小さな UI の直し](ui-cleanup.md#f47-小さな-ui-の直し)）が、この機能の該当の部分を置き換える。

**右のコメントと、本文の対象を、線で結ぶ**（利用者の依頼：2026-11-23。「右のコメントと本文の対象部分と何かしら線で繋げて関連を表現してほしい。イメージは draw.io の line で繋がってる感じ」）：

- (1) 右のパネルに**カードとして出ているスレッド**と、本文の対象（文の強調・ブロック・範囲）を、**線**（水平に出入りする S 字のベジェ）で結ぶ。端点：本文側は、複数行の強調なら**最後の行の右端の中央**・画像／図は**その要素の右端**・ブロック・範囲の枠は右端の縦の中央（版で変えたブロックの緑の線・入力中の範囲のハンドルに、点が重ならないよう、少しずらす）。カード側は、カードの左端。
- (2) 既定は、静か：**1px・アクセントの 35%**。選んでいる・マウスで光らせている（カードと本文のどちらでも）スレッドの線は、**1.5px・100%・手前**（ほかは、少し薄く）。入力中の対象は**破線**。解決済み（解決済みのタブで、カードが出ているとき）は、灰色。
- (3) **端点が、見える範囲（本文・パネル）の外のとき**：**縁に寄せた線は、選んでいる（active）・光らせている（linked）・入力中のスレッドだけ**に引く（外の端は、縁の内側に、短く止める）。**それ以外は、両端が、見える範囲の中にあるときだけ**引く（本文だけをスクロールして、見えている本文と見えているカードが対応しないとき、縁に寄せた線が、本文の上に束にならないように）。**両端が、同じ側の外なら、選んでいても、引かない**。本文の中の横スクロール（`pre`・表）の外に隠れた強調には、引かない。本文とパネルは、別々にスクロールしても、線は追従する。
- (4) 線は、**押せない**（`pointer-events: none`。線の下の文字は、選べる）。**`#article` の DOM には、何も足さない**（画面に固定の `<svg id="links">` に描く）。上のバー・左の一覧には、はみ出さない。
- (5) **右のパネルの見出し「コメント」の右端に、トグル**（名前は**「関連の線」**：状態を名前に入れない〔0.27.2 で、「関連の線を出す」から直した。名前が動作なのに `aria-pressed` が状態を言い、食い違っていたため〕。状態は、`aria-pressed` と `title`〔「いま：オン／オフ」「押すと、隠します／出します」〕で言う。**既定はオン**。`localStorage` の `rikai-ui` の `links` に保存。オフなら、線の要素ごと出さない）。
- (6) **同じ行の、複数のコメント**（利用者の質問と依頼：2026-11-23。「同じ行に別々のコメントがあった場合の表示は？」→「改善できますか」。3 件以上で、3 個目の丸が行の下にはみ出す・線が扇状に出て交差する、を実測した）：**丸**（F22）：同じ行（高さの差 4px 未満）の丸は、**折り返さず、右詰めで、2px ずつ重ねて**（白い縁の輪）並べる。**丸の幅は、文字数で決め、`width` で固定する**（1 文字 18px・2 文字 24px・3 文字 31px・4 文字 38px。数字が次の丸に隠れず、左端も切れない。並べる数を決める見積り〔`badgeWidth`〕と、実際の幅は、±0.5px で一致する）。**左の見える幅に収まる数だけ**並べる（5 つ並ぶ幅があれば、5 件ちょうどは 5 つ。**6 件以上は、先頭 4 つと「+N」**。1 つも収まらなければ「+N」だけ）。「+N」は、押すと、まとめた分でいちばん小さい番号のカードだけを見る・マウスを置くと、まとめた丸が、**小さなポップオーバー**（`.bno-pop`）に、実際の大きさで開く（**「+N」の真下**：左端は `max(本文の見える範囲の左 +4px, 「+N」の右端 − ポップオーバーの幅)`。**下に入りきらなければ、行の上に開く**。横に並べて、折り返す。「+N」と 2px 重ね、「+N」から丸へ下りる間は閉じない。ポップオーバーの丸も押せる）・カードにマウスを置くと、まとめた分のどれでも「+N」が光る。丸が記事の左に収まるよう、本文の左の余白を広げる（広い窓〔901px 以上〕で 36px。狭い窓〔900px 以下〕は、これまでの 8px のまま。5 つ並ぶのは、広い窓だけ）。**線**：**すべての線が、同じ x（記事の右端 +6px。カードから 24px 以上離す）まで、水平に引き出して**から、同じ x の範囲で S 字に入る。**引き出しの高さは、強調の矩形の下端 + 2px（行間）**（文字を貫かず、次の行にかからない）。**1 件だけの行は、点を、強調の右端の中央に置き**、そこから 10px 右へ小さく曲がって、行間の高さへ下りる。同じ行（高さの差 4px 未満）は、**カードの高さの順に、2px ずつ**ずらす（行間の中に収める：行間が狭ければ減らし、2px 以下なら 0）。始点の順とカードの順がそろうので、**同じ行も、隣の行も、線が交差しない**。**実際に引く線だけ**で、組・ずらし・引き出しを決める（引かれないカードは、場所を取らない）。**引き出しの部分だけを、別の線（`.cn-lead`）にして、薄い点線**（不透明度 0.17。S 字は 0.35）にする（強調の後ろの文字に、下線のように見えないように）。選んでいる・光らせている線は、引き出しも、実線・100%。縁に寄せた線は、引き出し線を使わない。**対象外**：本文以外（左の一覧）との線・線の色の選択・線の手での編集（つなぎ替え・動かす）・**カードの順が、本文の順と違うときの交差**（「すべて」タブで、解決済みを後ろに並べたときなど）。**既知の制約**：`pre` に 2 件以上が同じ行にあるときは、ずらしが 0 になり、2 本が重なって見える（交差はしない）・「+N」から、ポップオーバーへ、斜めに突っ切る動き（特に「+N」だけの行）では、閉じることがある

### F36 外観のモードを選べる

**外観のモード（ライト・ダーク・システム）を選べる**（利用者の依頼：2026-11-23。「ライトモードとダークモードとシステム自動モードみたいな、モードカラーリングを実装できる？」）：

- (1) 3 つのモード：`light`・`dark`・`system`。**既定は system**（OS の外観に従う。OS の外観が変わったら、再読み込みなしで追従する）。
- (2) **上のバー**（進み具合の左）に、**アイコン 1 つのボタン**（`#btn-theme`。`Monitor`・`Sun`・`Moon`）。押すと、system → light → dark → system と巡る。`aria-label`・`title` は、「外観：ライト。押すと、ダークにします」の形。
- (3) 選んだモードは、`localStorage` の `rikai-ui` の `theme` に保存し、再読み込みしても残る。**壊れた JSON・知らない値・型違いは、system に戻る**（幅・開閉・`links` は、保たれる）。
- (4) **配色**（ライト／ダーク）：背景・本文 `#fff`／`#09090b`・面 `#fafafa`／`#111113`・カード `#fff`／`#18181b`・罫線 `#e4e4e7`／`#27272a`・入力欄などの罫線（`--line-strong`）は、ダークで `#52525b`・文字 `#18181b`／`#fafafa`・補助 `#63636b`／`#a1a1aa`・アクセント（線・輪）`#2563eb`／`#60a5fa`・リンク `#1d4ed8`／`#93c5fd`・**白文字を載せる塗りは、塗り用のトークン**（主ボタンは両方 `#2563eb`。解決済みの丸は `--done-fill`：白文字で 7.73:1。**文字用の色を、塗りに使わない**）・コメントの強調の琥珀は、ダークで `rgba(251,191,36,.22)`・ダークの `#actbar`・トーストは、1px の縁（`--tip-edge`）。**見えている文字のコントラストは、ライト・ダークとも、WCAG AA（4.5:1）以上**（無効の主ボタン・placeholder・解決済み・`#actbar`・範囲選択のヒント・トースト・「+N」のポップオーバー・強調の中の文字を含む）。
- (5) **Mermaid の図**：ライトは `neutral`・ダークは `dark`（`securityLevel: 'strict'`・無害化は、変えない。ダークのときだけ、`themeVariables`：pie の色〔`pie1`〜`pie12`〕・線・凡例・影なし）。外観が変わったら（ボタンでも、OS の変化でも）、本文と返信の図を描き直す。**描画は、1 本の連鎖**にして、毎回、外観を設定してから描き、**描き終えた時点で、いまの外観が違えば、キャッシュにも画面にも入れず、捨てる**（描画待ちの間に外観を変えても、違う外観の図が、残らない）。
- (6) **範囲選択の画像**（F25）：地の色は、画面の紙の色（ダークでは、暗い地・明るい文字の画像が、AI に届く）。
- (7) **方式**：CSS の `color-scheme` と `light-dark()`（`:root { color-scheme: light dark }`。`data-theme="light"`／`"dark"` で固定。system は属性なし）。**ちらつき（FOUC）を避けるため、`app/src/web/public/assets/theme-init.js`（同期・外部ファイル）を、`<head>` の CSS より前に置き**、保存した外観を、最初のフレームから効かせる（CSP が `script-src 'self'` で、インラインのスクリプトは使えないが、外部ファイルは許される。規則は、`parseTheme` と同じ）。`main.tsx` の `applyTheme` も、残す。
