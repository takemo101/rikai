# 資料の書式

この文書は、[SPEC.md](../../SPEC.md) の「機能要件」のうち、**資料の書式**（F9・F17・F26・F52）を扱う。[SPEC.md の機能一覧へ戻る](../../SPEC.md#3-機能要件)。実装の状態・確認は [docs/status.md](../status.md)。

本文中の「§6」「§7」「§8」は、[SPEC.md](../../SPEC.md) の同じ番号の節を指す（§6＝実装の状態〔[status.md](../status.md)〕・§7＝未決事項・§8＝利用者の判断〔[docs/decisions/](../decisions/README.md)〕）。本文は、SPEC.md の表の行から、文言を変えずに移した。

### F9 返信は Markdown

**返信は Markdown**：見出し・表・箇条書き・コード・Mermaid の図・画像が使える。ビューアは、スレッドの中にそのまま描く

### F17 画像は assets のものだけ

**画像は、トピックの `assets/` のものだけ**：資料・返信の `![…](assets/名前)`（または相対パス）は、`assets/` から配信する。外部の画像 URL は表示しない（「外部画像は表示しません」と出す）。`data:image/` は表示する

### F26 コードブロックの種類で形式を書ける

**資料に、コードブロックの種類で、形式を書ける**（sideshow を参考に。JS を動かさないものだけ）：```` ```diff ````（行の種類で色分け：追加・削除・`@@`・ファイルの見出し。`@@` のあと次の `diff ` までは、`---`・`+++` で始まる行も、削除・追加）・```` ```json ````（折りたためる木。根と深さ 1 までは開く。**書かれたとおりに見せる**：数・文字列・キーは、元の文字のまま〔桁あふれする整数・`1.50`・`-0`・`\n` の表記・重複したキー・キーの順を、変えない〕。JSON として読めない・3000 ノード超・深さ 40 超は、ふつうのコードブロック）・```` ```terminal ````／```` ```ansi ````（ANSI の色〔SGR。基本の 16 色・太字・薄字・斜体・下線〕。ESC は、制御文字・`\x1b`・`\x1B`・`\u001b`・`\033`・`\e`・`␛`・`^[` を受ける。色以外の制御文字・シーケンスは捨てる）・```` ```trace ````（`名前 | 開始ms | 長さms | メモ` の行から、ウォーターフォール。最大 200 行。読めない行があればふつうのコードブロック）。**資料の文字は、`app/src/web/doc/render/fmt.ts` で escape して、決まったタグ・クラスの中に入れ、そのあと、これまでと同じ DOMPurify を通す**（`style` 属性は使えないので、trace の棒の位置は、数だけから、無害化のあとに設定する）。AI の返信（Markdown）にも使える（返信の中でも、同じ見た目）。コメントの位置づけは、ブロック（種類のラベル：「差分」「JSON」「端末出力」「トレース」）と、文の選択のまま。形式の各行・各項目は、改行で終わる（引用・AI に届くブロックの文字が、読める形になる）。画面の補助の文字（JSON の個数・trace の軸の目盛り）は、文字にせず、CSS で出す。**コードの色分け（言語別）・JS を動かす `html` は、含まない**（SPEC §7・N3）

### F52 資料に draw.io の図を埋め込める

**資料（と AI の返信）に、`drawio` コードブロックで、draw.io の図を埋め込める**（利用者の依頼：2026-11-24。「マークダウンの中にドロー IO の XML を埋め込んで、それを描画することって可能 …〔添付：スイムレーンの業務フローの画像〕… 以下のように業務フローやシーケンスが書けると嬉しい。mermaid と同じく拡大して範囲選択してコメント入れられるようにしたい」→「対応してみて欲しい」→ 利用者が、見本で確認して、「問題ない」と承認した。0.32.0。RIK-065。理由と判断：[ADR-0055](../decisions/0055-drawio-block.md)）：

- **(1) 記法**：```` ```drawio ```` の中に、`<mxGraphModel>`、または、`<mxfile><diagram>` の XML を書く。**圧縮形式**（base64 + deflate-raw + URI エンコード）も、`DecompressionStream` で展開して描く（AI が書くときは、圧縮しない `<mxGraphModel>` を書く）。**Mermaid の図と同じ経路**（本文のブロック・インライン SVG に描く）で、**F37 の拡大・F43 の拡大表示（ズーム・移動・範囲を選んでコメント・ドック）・F25 の範囲コメント・F22 の番号・線が、そのまま動く**。ブロックにマウスを置くと出る「コメント」「拡大表示」も、ほかのブロックと同じ。版の差分（F11）では、図のソースが変われば「変更」・同じなら変更なし。並べて比べる（F44）にも、出る。
- **(2) 対応する記法**：**図形**（四角・角丸・楕円・菱形・円柱〔`cylinder3`・`cylinder`〕・`process`・`parallelogram`・`hexagon`・`document`・`triangle`・`text`・アクター・`umlLifeline`・`mxgraph.flowchart.*` の主なもの）・**構造**（スイムレーン〔`startSize`・`horizontal=0|1`・`swimlaneFillColor`〕・表〔`table`・`tableRow`・`partialRectangle`〕・`object`・`UserObject`・複数レイヤー・`visible=0`・`edgeLabel`）・**線**（直交・肘・直線・経由点・`exit*`・`entry*`・自己ループ・`rounded`・`classic`／`block`／`open`／`oval`／`diamond`／`none`・`dashed`・ラベルの位置・オフセット）・**文字**（`html=1` のタグ外し・`whiteSpace=wrap` の自動折り返し〔日本語・行頭禁則・canvas で幅を測る〕・`fontStyle`・揃え・外側のラベル・縦書き）。
- **(3) 対応しない記法**：**未対応の shape は、四角で描き**、図の下に「未対応の図形（…）は、四角で描きました」と出す。画像・リンク・`rgb()`・`url()` は、出さない（色の無視は、図の下に記録）・`<mxfile>` の複数ページは、最初のページだけ・曲線の線・他の図形を避ける経路探索・グラデーション・影・HTML ラベルの太字・斜体（タグは捨てる。`fontStyle` は使える）・`fontFamily` の指定（固定のフォント）。**DOCTYPE・ENTITY は、拒否する**。
- **(4) 上限**：XML **500KB**・セル **2000**・座標 **±100000**・入れ子 **25**・圧縮の展開後 **2MB**。**超えたら、理由とソースを、文字で出す**。失敗の表示は、Mermaid と同じ（`.mermaid-error`・`.mm-err`・`pre`）で、理由を足した。存在しない `parent` は、最上位として描き、記録が出る。長さが 4000 を超えるスタイルは、超えた分を読まない。
- **(5) N1・N3 を弱めない**：**図の XML は、スクリプトにならず、外部の資源を読まない**。**SVG は、`createElementNS`・`setAttribute`・`textContent` だけで組み立てる**（`innerHTML` を使わない。`style` 属性・`foreignObject`・`href`・`<image>` も、作らない）。**色は、`#rgb`・`#rrggbb`・`#rrggbbaa`・`none`・`inherit`・CSS の色名・`light-dark(a,b)` だけ通す**。公式のビューア（`viewer-static.min.js`）は、使わない（外部資源・スクリプトの実行・サイズ：ADR-0055）。
- **(6) 図に `id` も `url(#…)` も出さない**：**矢印は、`<marker>` でなく、多角形で描く**。拡大表示の複製（`zoom-` 接頭辞：F37）でも、範囲の切り出し（SVG を単独の画像にする：F25）でも、壊れない。
- **(7) ダークモード**：標準の色は、`var(--dx-ink, #リテラル)` のように、トークン（`app.css` の `--dx-ink`・`--dx-fill`）とリテラルを併記する（範囲の切り出し画像は、ページの CSS を持たないので、描いた時点の外観のリテラルが入る：**外観が変わったら、描き直す**）。指定した地の上の、色指定のない文字は、地に合わせて黒か白にする。**例外：「指定の色は、そのまま」の例外として、純粋な黒の線・文字と、純粋な白の地は、標準の色として扱う**（draw.io のダークモードの反転と同じ向き。ダークで、黒い矢印が消えないように）。**それ以外の色は、そのまま**。線の上のラベルは、既定で、紙の色の地を敷く（`labelBackgroundColor=none` で外せる）。
- **(8) 図の判定**：ラベル「図」・差分の文字・アンカーの文字・文字の数え方は、Mermaid と同じ判定（`blocks.ts` の `DIAGRAM_SEL`・`isDiagram`）。`focusable.ts`・`region.ts`・`selection.ts` も、同じ判定。
- **(9) 変えないもの**：サーバー・API・`.rikai/` のデータの形（図の XML は、資料の本文の一部）。**バンドル**：図のある資料でだけ、`drawioRender` の chunk（31.9KB・gzip 13KB）を読む（`index.js` は +1,273 B）。
- **(10) 残る課題**：**本物の draw.io が出す XML は、手元で draw.io を動かせないため、仕様と典型の形から書いて確かめた：実際のファイルでの確認は、人手が要る**。経路は簡易で、他の図形を避けない（複雑な図では、経由点が要る）。**見本との違い**（目視）：文字の行間（見本は約 1.7 倍・こちらは 1.2 倍）・色は測っていない（目視で近似）・見本の最下部の点線の切れ目〔レーンが破線で続く〕は、再現していない。曲線・グラデーション・影は、未対応。**確認していない範囲**：実際のマウス・他のブラウザ・スクリーンリーダー
- **(11) AI への指示**：`skills/rikai/references/drawio.md`（書式の手引き）と、`SKILL.md` の「補助を読む場面」・コードブロックの形式の一覧に、`drawio` を足した（[F18](ai-commands.md#f18-エージェントのスキルとして使える)）。**返信の `body` でも、描かれる**（`Message.tsx` が `fillDiagrams` を使う）。
