### F9 返信は Markdown

**返信は Markdown**：見出し・表・箇条書き・コード・Mermaid の図・画像が使える。ビューアは、スレッドの中にそのまま描く

### F17 画像は assets のものだけ

**画像は、トピックの `assets/` のものだけ**：資料・返信の `![…](assets/名前)`（または相対パス）は、`assets/` から配信する。外部の画像 URL は表示しない（「外部画像は表示しません」と出す）。`data:image/` は表示する

### F26 コードブロックの種類で形式を書ける

**資料に、コードブロックの種類で、形式を書ける**（sideshow を参考に。JS を動かさないものだけ）：```` ```diff ````（行の種類で色分け：追加・削除・`@@`・ファイルの見出し。`@@` のあと次の `diff ` までは、`---`・`+++` で始まる行も、削除・追加）・```` ```json ````（折りたためる木。根と深さ 1 までは開く。**書かれたとおりに見せる**：数・文字列・キーは、元の文字のまま〔桁あふれする整数・`1.50`・`-0`・`\n` の表記・重複したキー・キーの順を、変えない〕。JSON として読めない・3000 ノード超・深さ 40 超は、ふつうのコードブロック）・```` ```terminal ````／```` ```ansi ````（ANSI の色〔SGR。基本の 16 色・太字・薄字・斜体・下線〕。ESC は、制御文字・`\x1b`・`\x1B`・`\u001b`・`\033`・`\e`・`␛`・`^[` を受ける。色以外の制御文字・シーケンスは捨てる）・```` ```trace ````（`名前 | 開始ms | 長さms | メモ` の行から、ウォーターフォール。最大 200 行。読めない行があればふつうのコードブロック）。**資料の文字は、`app/src/web/doc/render/fmt.ts` で escape して、決まったタグ・クラスの中に入れ、そのあと、これまでと同じ DOMPurify を通す**（`style` 属性は使えないので、trace の棒の位置は、数だけから、無害化のあとに設定する）。AI の返信（Markdown）にも使える（返信の中でも、同じ見た目）。コメントの位置づけは、ブロック（種類のラベル：「差分」「JSON」「端末出力」「トレース」）と、文の選択のまま。形式の各行・各項目は、改行で終わる（引用・AI に届くブロックの文字が、読める形になる）。画面の補助の文字（JSON の個数・trace の軸の目盛り）は、文字にせず、CSS で出す。**コードの色分け（言語別）・JS を動かす `html` は、含まない**（SPEC §7・N3）

### F52 資料に draw.io の図を埋め込める

**資料（と AI の返信）に、`drawio` コードブロックで、draw.io の図を埋め込める**（利用者の依頼：2026-11-24。「マークダウンの中にドロー IO の XML を埋め込んで、それを描画することって可能 …〔添付：スイムレーンの業務フローの画像〕… 以下のように業務フローやシーケンスが書けると嬉しい。mermaid と同じく拡大して範囲選択してコメント入れられるようにしたい」→「対応してみて欲しい」→ 利用者が、見本で確認して、「問題ない」と承認した。0.32.0。RIK-065。理由と判断：[ADR-0055](../decisions/0055-drawio-block.md)）：

- **(1) 記法**：```` ```drawio ```` の中に、`<mxGraphModel>`、または、`<mxfile><diagram>` の XML を書く。**圧縮形式**（base64 + deflate-raw + URI エンコード）も、`DecompressionStream` で展開して描く（AI が書くときは、圧縮しない `<mxGraphModel>` を書く）。**Mermaid の図と同じ経路**（本文のブロック・インライン SVG に描く）で、**F37 の拡大・F43 の拡大表示（ズーム・移動・範囲を選んでコメント・ドック）・F25 の範囲コメント・F22 の番号・線が、そのまま動く**。ブロックにマウスを置くと出る「コメント」「拡大表示」も、ほかのブロックと同じ。版の差分（F11）では、図のソースが変われば「変更」・同じなら変更なし。並べて比べる（F44）にも、出る。
- **(2) 対応する記法**：**図形**（四角・角丸・楕円・菱形・円柱〔`cylinder3`・`cylinder`〕・`process`・`parallelogram`・`hexagon`・`document`・`triangle`・`text`・アクター・`umlLifeline`・`mxgraph.flowchart.*` の主なもの）・**構造**（スイムレーン〔`startSize`・`horizontal=0|1`・`swimlaneFillColor`〕・表〔`table`・`tableRow`・`partialRectangle`〕・`object`・`UserObject`・複数レイヤー・`visible=0`・`edgeLabel`）・**線**（直交・肘・直線・経由点・`exit*`・`entry*`・自己ループ・`rounded`・`classic`／`block`／`open`／`oval`／`diamond`／`none`・`dashed`・ラベルの位置・オフセット）・**文字**（`html=1` のタグ外し・`whiteSpace=wrap` の自動折り返し〔日本語・行頭禁則・canvas で幅を測る〕・`fontStyle`・揃え・外側のラベル・縦書き）。
- **(3) 対応しない記法**：**未対応の shape は、四角で描き**、図の下に「未対応の図形（…）は、四角で描きました」と出す。画像・リンク・`rgb()`・`url()` は、出さない（色の無視は、図の下に記録）・`<mxfile>` の複数ページは、最初のページだけ・曲線の線・他の図形を避ける経路探索・グラデーション・影・HTML ラベルの太字・斜体（タグは捨てる。`fontStyle` は使える）・`fontFamily` の指定（固定のフォント）。**DOCTYPE・ENTITY は、拒否する**。
- **(4) 上限**：XML **500KB**・セル **2000**・座標 **±100000**・入れ子 **25**・圧縮の展開後 **2MB**。**超えたら、理由とソースを、文字で出す**。失敗の表示は、Mermaid と同じ（`.mermaid-error`・`.mm-err`・`pre`）で、理由を足した。存在しない `parent` は、最上位として描き、記録が出る。長さが 4000 を超えるスタイルは、超えた分を読まない。
- **(5) N1・N3 を弱めない**：**図の XML は、スクリプトにならず、外部の資源を読まない**。**SVG は、`createElementNS`・`setAttribute`・`textContent` だけで組み立てる**（`innerHTML` を使わない。`style` 属性・`foreignObject`・`href`・`<image>` も、作らない）。**色は、`#rgb`・`#rrggbb`・`#rrggbbaa`・`none`・`inherit`・CSS の色名・`light-dark(a,b)` だけ通す**。公式のビューア（`viewer-static.min.js`）は、使わない（外部資源・スクリプトの実行・サイズ：ADR-0055）。
- **(6) 図に `id` も `url(#…)` も出さない**：**矢印は、`<marker>` でなく、多角形で描く**。拡大表示の複製（`zoom-` 接頭辞：F37）でも、範囲の切り出し（SVG を単独の画像にする：F25）でも、壊れない。
- **(7) ダークモード**：標準の色は、`var(--dx-ink, #リテラル)` のように、トークン（`app.css` の `--dx-ink`・`--dx-fill`）とリテラルを併記する（範囲の切り出し画像は、ページの CSS を持たないので、描いた時点の外観のリテラルが入る：**外観が変わったら、描き直す**）。指定した地の上の、色指定のない文字は、地に合わせて黒か白にする。**例外：「指定の色は、そのまま」の例外として、純粋な黒の線・文字と、純粋な白の地は、標準の色として扱う**（draw.io のダークモードの反転と同じ向き。ダークで、黒い矢印が消えないように）。**それ以外の色は、そのまま**。線の上のラベルは、既定で、紙の色の地を敷く（`labelBackgroundColor=none` で外せる）。
- **(8) 図の判定**：ラベル「図」・差分の文字・アンカーの文字・文字の数え方は、Mermaid と同じ判定（`blocks.ts` の `DIAGRAM_SEL`・`isDiagram`）。`focusable.ts`・`region.ts`・`selection.ts` も、同じ判定。
- **(9) 変えないもの**：サーバー・API・`.rikai/` のデータの形（図の XML は、資料の本文の一部）。**バンドル**：図のある資料でだけ、`drawioRender` の chunk（31.9KB・gzip 13KB）を読む（`index.js` は +1,273 B）。
- **(10) 残る課題**：**本物の draw.io が出す XML は、手元で draw.io を動かせないため、仕様と典型の形から書いて確かめた：実際のファイルでの確認は、人手が要る**。経路は簡易で、他の図形を避けない（複雑な図では、経由点が要る）。**見本との違い**（目視）：文字の行間（見本は約 1.7 倍・こちらは 1.2 倍）・色は測っていない（目視で近似）・見本の最下部の点線の切れ目〔レーンが破線で続く〕は、再現していない。曲線・グラデーション・影は、未対応。**確認していない範囲**：実際のマウス・他のブラウザ・スクリーンリーダー
- **(11) AI への指示**：`skills/rikai/references/drawio.md`（書式の手引き）と、`SKILL.md` の「補助を読む場面」・コードブロックの形式の一覧に、`drawio` を足した（[F18](ai-commands.md#f18-エージェントのスキルとして使える)）。**返信の `body` でも、描かれる**（`Message.tsx` が `fillDiagrams` を使う）。

### F57 資料に数式を書ける

**資料（と AI の返信）に、数式を、GitHub と同じ 3 種類の書き方で書ける。KaTeX（0.18）で描く**（利用者の依頼：2026-11-26。「markdown 表示で数式表示に対応してる？（`$$x = \frac{-b \pm \sqrt{b^2 - 4ac}}{2a}$$`）」→ GitHub の書き方と、MathJax でなく KaTeX を示し「よし GitHub と同じく 3 種類対応にしましょう。そして KaTeX にしましょう」→ 見本で「問題ないです」）。0.1.8。設計の判断は [ADR-0062](../decisions/0062-math-katex.md)。

- **(1) 記法**（`doc/render/mathSyntax.ts`。`marked` の拡張）：数式になるもの：文中 `$x$`・`` $`x`$ ``（Markdown の記号と衝突するとき）・文中の `$$x$$`・別行 `$$…$$`（1 行でも複数行でも）・` ```math `。**数式にしないもの**：通貨 `$5 と $10`・直前が空白、または直後が数字の閉じる `$`・`\$`・コードスパン・コードブロックの中・空の式・空行をまたぐ式・閉じていない `$$`（**迷うものは、ふつうの文字のまま**）。
- **(2) 描画**（`doc/render/math.ts`）：KaTeX を**動的 import**（数式のない資料では、KaTeX・CSS・フォントを読まない）。`fillDiagrams` が呼ぶので、本文・返信・並べて比べる画面で、同じに動く。構文の誤りは、Mermaid と同じ見た目で、理由と元の TeX を文字で出す。**上限**：ソース 20,000 文字・出力 1.5MB・`maxExpand` 1000・`maxSize` 50em・式ごとにキャッシュ・重い式は 12ms ごとに画面へ制御を返す。
- **(3) 別行の数式は、図と同じブロック**：`DIAGRAM_SEL` に `.math-block`・ラベル「数式」・差分の文字・アンカー・`textIndex` から除外・`focusable` の入口を図と同じに。**選択・拡大表示（F37・F43）・範囲コメント（F25）・版の差分（F11）・並べて比べる（F44）まで通る**。拡大表示は、HTML をそのまま `transform: scale` で拡大する（`focus/zoomMath.ts`。`LightboxTarget` に `math`）。範囲を選ぶ基準の箱は、式そのもの（`.katex`）。**拡大表示の入口の不具合**（利用者の報告：2026-11-26。「拡大表示ボタンが出てこないケースがある」：行列の式のブロックで、バーに「コメント」だけ）：`zoomTargetOfBlock` が、ブロックの中の `img`・`svg` だけを探していたため、svg を含まない式（行列・分数・和）は対象が見つからなかった → `.math-block` なら、`.katex` を式そのものとして対象にする。描画前に出したバーは、描画が終わったら出し直す（`ActionBar.tsx`）。複数の式を含むブロックは、ブロック全体を 1 つの `.katex` の箱として拡大する。
- **(4) 元の TeX を、本文の文字として持つ**：文中の数式は、元の TeX を本文の文字として持ち、描いたあとは幅ゼロで見えなくする。描画後の KaTeX の HTML・MathML の文字は、`textIndex`・ブロックのハッシュ・差分から除く（`.math-out`）：**描画の前後で、ハッシュ・引用・差分の文字が変わらない**。AI に届く引用にも、TeX が入る。コメントの強調は、見えない元の文字に付くので、描いた式にも、同じ印を CSS の `:has()` で写した。コピーすると、元の TeX が入る。
- **(5) 範囲の画像にフォントを入れる**：範囲の画像は、HTML を `foreignObject` の画像にするが、その中では `@font-face` の URL を読めない → 使う面の woff2 だけを、同じオリジンから読み、`data:` にして入れる（`interact/katexFonts.ts`）。
- **(6) サニタイズ（N3 を弱めない）**：**本文の `PURIFY` は、変えない**。KaTeX 専用の DOMPurify の別インスタンスで、許可リスト（リンク・画像・`foreignObject`・イベントハンドラは許さない）。`style` 属性は、`isSafeStyle` の許可リストと値の検査を通ったものだけ。結果は DocumentFragment のまま付け、**`innerHTML` は使わない**。**`trust: false`**（`\href`・`\url`・`\htmlClass` などは、命令名を赤い文字で出す）。
- **(7) フォントと CSP**：`font-src` を足さずに済んだ（`/assets/KaTeX_*.woff2` は `default-src 'self'` に収まる）。woff2 は**埋め込まない**設定（Vite の既定の `data:` 埋め込みは、Size3 が CSP に拒まれる）。woff2 は 20 個（合計 259,792 B。使う面だけを遅延で読み、通常の式で 3〜7 個）。外への通信は 0 件（フォントも 127.0.0.1）。**ライセンス**：KaTeX 本体は MIT・フォントは SIL OFL 1.1 → `THIRD-PARTY-LICENSES.txt` に、全文と著作権表示を入れた。**サイズ**：`index.js` +11,447 B（gzip +3,615 B）・`index.css` +1,868 B・`katex.js` 259,046 B（mermaid と共有）・`katex.css` 22,276 B（数式があるときだけ読む）。
- **(8) AI への指示**：`skills/rikai/references/doc-format.md` に、数式の書き方（GitHub と同じ 3 種類・通貨との区別）がある（[F18](ai-commands.md#f18-エージェントのスキルとして使える)）。
- **(9) 既知の点**：コピーすると、数式の前後に改行が入る（中身は元の TeX）・KaTeX の MathML のうち `\ulcorner` などと、`\fcolorbox` の MathML 側の `border` は、サニタイズで落ちる（表示は変わらない）・本文のリストの項目の中の別行数式は、拡大できるが、範囲選択はできない・`\tag` は、式の右に続ける表示（KaTeX 本来の右端寄せではない）・描画前のバーの出し直しは、実 Chrome の遅延での自動テストがない・**実際のマウス・他のブラウザ・スクリーンリーダーは、未確認**。

### F58 資料に注意書きとタスクリストを書ける

**資料（と AI の返信）に、GitHub と同じ書き方で、注意書き（アラート）とタスクリストを書ける。どちらも、表示だけ**（利用者の依頼：2026-11-26。他に対応した方がよい描画の候補を示したうえで「以下も対応してほしい：アラート（注意書き）・タスクリスト」→ 見本で「いい感じです」）。0.1.8。設計の判断は [ADR-0063](../decisions/0063-alerts-and-tasklist.md)。

- **(1) アラートの記法**：`> [!NOTE]`・`TIP`・`IMPORTANT`・`WARNING`・`CAUTION`。**本文の最上位の引用で、最初の行がマーカーだけのもの**を認める（`doc/render/callouts.ts`）。大文字・小文字は問わず、マーカーの行末の空白と `<br>` は許す。**同じ行に文字があるもの・知らない種類・リストや引用の中のものは、ふつうの引用のまま**（文字も変えない）。アラートの中の引用は、ふつうの引用（GitHub の公式文書：入れ子にできない。大文字・小文字と、同じ行の扱いは、二次情報）。
- **(2) 題とアイコン**：**DOM に文字を入れず**、CSS の疑似要素で描く。題は「メモ · Note」のように英語を併記（GitHub では WARNING が黄色・CAUTION が赤で、日本語だけだと重さが逆に見えるため）。アイコンは、lucide の線を CSS マスクにした（CSP の `img-src data:` の内側）。地は `--surface`・色は題・アイコン・帯だけ（「状態の色は塗らない」方針）。ライト・ダークとも AA。
- **(3) コメントと題**：**題の文字は、コメントに入らない**（マーカーの行を DOM から外すので、題は `textContent` に入らず、引用・`blockText`・ハッシュ・`textIndex` の対象外）。カードの見出し（`label`）だけ、「警告: …」のように種類を出す。アラートの中の文の選択・ブロックへのコメントは、ほかの引用と同じ。
- **(4) 差分（F11）**：アラートの種類とチェックの状態は、ハッシュではなく `sigTag`（版の対応づけ用）に入れる。差分のメモは「注意書き（警告）→ 注意書き（注意）」「箇条書き・チェック ☐ → 箇条書き・チェック ☑」。入れ子のチェックが変わっても、親の項目が変更になる。
- **(5) タスクリスト**：`- [ ]`・`- [x]`・`- [X]`（番号付き・入れ子・段落つきの項目。完了と未完了の混在）。**`input` は、許可しない**：`PURIFY` は、一切変えない。marked の `checkbox` の出力を、`<span class="task-box" role="checkbox" aria-checked aria-disabled aria-label>` に置き換え、`input` を作らない（`name`・`form` で送信に使える入口もできない）。先頭にない偽の印や、AI が HTML に直書きした `data-alert` と `<input>` は、消えるか落ちる。チェック欄は、押せない（`pointer-events: none`。クリックは項目に届き、文を選んでコメントする操作を妨げない）。**状態を変えるには、資料を直して、新しい版を出す**。完了の項目は、文字を薄くする（`--muted`。取り消し線は付けない）。
- **(6) 既存コメントへの影響**：普通の引用・リスト・番号つきリスト・タスク項目の `blockHash`・`blockId` は、変わらない。**変わるのは、`> [!NOTE]` で始まる引用のハッシュだけ**（例：`133qr4o` → `167v8sp`）。そのブロックのコメントは、同じ種類で内容が近いブロックとして、推定で見つかる（単体で確認）。ただし、**マーカーを選んで付けた文のコメントは、外れる**。

### F59 インライン SVG は本文の幅に応じて縮む

**資料（と AI の返信）に直接書いたインライン `<svg>` は、Mermaid・draw.io と同じように、本文の横幅に応じて縮む**（利用者の依頼：2026-11-27。背景：「SVG も使えるよね？拡大して範囲選択できるの？」→ 見本で検証〔6 種類の SVG：拡大・範囲・複製の id・落とすもの〕・14 個のサンプル集・Mermaid・draw.io との比較の見本 →「インライン SVG（Markdown に直接書いた `<svg>`）も、Mermaid・draw.io と同じように本文の横幅に応じて伸縮するようにして欲しい」）。0.1.8。設計の判断は [ADR-0064](../decisions/0064-svg-fit.md)。

- **(1) CSS**（`app.css`・2 行）：対象は、`:is(#article, .cmpcell.md, .msg .body.md) > svg` と `> p > svg`。指定は `max-width: 100%; height: auto`。**直接の子（と `<p>` の子）だけ**：KaTeX・html-app・UI アイコン・拡大表示のステージ・範囲選択のオーバーレイを巻き込まない。**元の大きさ**：`width` 属性の値が上限（広げない：小さい SVG は拡大しない）。
- **(2) `viewBox` の補完**（`markdown.ts`）：`viewBox` がなく、`width`・`height` が、どちらも px の数のブロック `<svg>` に、`viewBox="0 0 幅 高さ"` を足す（無害化のあと、検査した数だけから作る：`PURIFY`・CSP は変えない）。足さないと、枠だけが縮んで、図形は縮まず、はみ出した部分が切れる。`viewBox` のみ・`width="100%"`・`width="100%" height="200"` は、変化なし。`width` だけで `viewBox` がないものは、補完しない（幅は縮み、高さは変わらず、図形は切れる）。
- **(3) 実測**（窓幅 1360／1100／760 → 列 634／704／420px）：1200×800・`<p>` 包みは、列幅に縮む（縦横比 1.5 のまま。右パネルを広げて列が狭くなっても追従）・600×300 は、列が 600 より狭いときだけ縮む・80×80 は、80 のまま。変更を重ねる・並べて比べる・返信内の SVG・ダークでも縮む。
- **(4) 拡大表示・範囲**：拡大表示の `svgNaturalSize` は、複製の属性（`viewBox` → `width`・`height`）を読むので、縮んだ大きさは使わない（窓幅 760・列 420px で開いて、1200×800 のまま）。範囲の枠は、本文・拡大表示・再読み込み後・右パネル幅の変更後で、目印の矩形に 2px 以内で重なる。拡大表示で付けた範囲は、本文でも同じ角に重なる。**以前の不具合（列より広い SVG は、はみ出た部分を本文で選べない）は、解消**。
- **(5) 範囲の画像の修正（想定外。元からあった不具合）**：範囲コメントの画像で、ブロックそのものが `<svg>` のとき、**範囲の位置に関係なく、図の左上が写っていた**（AI に届く添付画像が誤る：SVG の見本の検証で見つかった）。`region.ts` で、位置指定を SVG にも効かせ、`max-width`・`max-height: none` を足した。
- **(6) AI への指示**：`skills/rikai/references/doc-format.md` に 1 行（列より広い SVG は、自動で縮む。`viewBox` を付ける）。
- **(7) 既知の点**：`<div>`・`<figure>` に包んだ SVG は縮まない・`width` だけで `viewBox` のない SVG は、枠が縮んで図形が切れる・**SVG の中に `<a href="https://…">` を書くと、資料の本文全体が「本文を表示できませんでした」になる（コードの不具合の可能性・未修正）**・SVG の中の `<filter>`・`<use>`・`<style>`・`<script>`・`<foreignObject>`・`<animate>` は、無害化で消える（`filter` を付けた図形は、見えなくなる）・並べて比べるで、v1 と v2 が同じ `id` を違う内容で定義していると、右の図が左の定義で描かれる・拡大表示を Esc で閉じても、元の SVG にフォーカスが戻らない・外部の `<image href>` は、壊れた画像の印が出る（通信は CSP で遮断）・インライン SVG は、差分で、箱の位置や線の変更が出ない（文字だけ）・**実際のマウス・他のブラウザは、未確認**。
